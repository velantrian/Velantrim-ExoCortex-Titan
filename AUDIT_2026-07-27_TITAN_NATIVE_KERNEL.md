## 2. 🧬 Как работают системы

### 2.1 Native Kernel — канон, а не код

Трёхуровневое разделение (`ARCHITECTURE.md:15–54`):

```text
Architecture Canon          ← устойчивый смысл (что означает «знать»)
   ↓
Abstract Contracts          ← требуемое поведение без технологии
   ↓
Implementation Profiles     ← SQLite / Python / CPU — сменные детали
```

Форма канона (`ARCHITECTURE.md:56–66`):

```text
Claim → Event → детерминированная редукция → Epistemic State
      → сменные проекции → задаче-специфичный отбор контекста → Receipt
```

**Ключевая идея:** текущее состояние **выводится** из append-only истории событий, а не хранится как изменяемая строка. Проекции (SQLite-таблицы, FTS, векторные индексы, графовые смежности) — расходный материал: их можно удалить и пересобрать. Это то, что делает архитектуру технологически нейтральной: заменяя SQLite на другой субстрат, вы меняете проекцию, а не смысл.

**Эпистемическая граница** (`ARCHITECTURE.md:154–182`) — самая оригинальная часть:

```text
представление      ≠ представляемая реальность
наблюдение         ≠ объяснение
преобразование     ≠ происхождение
неизвестное        ≠ ложное
текущий предел     ≠ универсальная невозможность
мировоззрение      ≠ неотмеченный эмпирический факт
```

Это формализовано как `NK-EPI-001…008` — восемь проверяемых утверждений. Инвариант №30 — сердце системы: *«Ни одно наблюдение, модель, гипотеза, результат поиска, полезный исход или предложение не может быть молча повышено до принятого знания.»*

### 2.2 Titan — многослойная память с обязательным гейтом записи

Реальный поток данных, восстановленный по коду:

```text
вход (HTTP / Telegram / файлы)
   ↓
🛡️ write_gate.admit_fact()          ← ОБЯЗАТЕЛЬНЫЙ, отключить нельзя
   │   WORLD_FACT без источника                → reject
   │   WORLD_FACT от LLM без evidence          → reject
   │   субъективное / UNKNOWN                  → allow (как Observed)
   ↓
🛡️ policy_kernel.canonical_write_decision()   ← SAFE_MODE блокирует все записи
   ↓
L0 raw_memory (иммутабельный)  →  L1 facts  →  L2 relations  →  L3 граф
   ↓
ESM-лестница: Observed → Hypothesized → Supported → Validated → ImmutableCore
   ↓
📜 VersionStore (pre-image) + AuditChain (hash-chain v2) в ОДНОЙ транзакции
```

**Что здесь сделано по-настоящему хорошо:**

`core/write_gate.py` — граница допуска, которую нельзя выключить:

```python
def is_write_gate_enabled() -> bool:
    """Compatibility readout: the mandatory gate is always enabled."""
    return True
```

Устаревший флаг `ENABLE_WRITE_GATE` читается для диагностики, но **не может** отключить проверку. Это правильный архитектурный выбор: канонические границы безопасности не должны быть «фичами».

`core/audit_chain.py` — версионированное каноническое хеширование (`HASH_VERSION_LEGACY = 1`, `HASH_VERSION_CURRENT = 2`, миграция `017_audit_chain_hash_v2.sql`) с явным полем `domain` вместо конкатенации через разделитель. Это в точности то, чего требует канон Native Kernel («hash domain/version separation») — и Titan это уже реализовал.

## 5. 🔴 Проблемы и уязвимости

### 5.1 🔴 КРИТИЧНО — Native Kernel: главный гейт проекта это неподписанный текст

Весь Track A Native Kernel зависит от перехода `UNVERIFIED_CANDIDATE → AUTHENTIC_RECOVERED`. Этот переход контролируется функцией `validate_governance()` в `tools/source_recovery/verify_manifest.py:88–112`, которая проверяет **строковые поля в редактируемом JSON**.

**Проверено экспериментально:**

```bash
# 1. Сгенерировали честный манифест кандидата
python3 tools/source_recovery/generate_manifest.py candidate --output m.json \
        --recovered-from "test" --recovered-by "auditor"

# 2. Вручную отредактировали три поля
#    snapshot_status              → "AUTHENTIC_RECOVERED"
#    provenance.operator_decision → "APPROVED"
#    authenticity.decision        → "APPROVED"  (+ decided_by/decided_at/rationale)

# 3. Верификатор принял подделку:
{ "ok": true,
  "snapshot_status": "AUTHENTIC_RECOVERED",
  "verified_files": 1,
  "errors": [] }
```

Нет подписи, нет HMAC, нет внешней аттестации, нет журнала. Любой, кто может редактировать файл, может объявить кандидата аутентичным.

**Почему это особенно остро:** репозиторий сам предупреждает (`docs/CONFORMANCE_MODEL.md:264`): *«❌ Operator approval is presented as empirical proof»* — а инструмент реализует именно этот антипаттерн.

**Усугубляющий фактор:** ветка `AUTHENTIC_RECOVERED` (строки 105–112) имеет **нулевое тестовое покрытие**. Все 4 теста создают только `UNVERIFIED_CANDIDATE` со статусом `PENDING`. Самая критичная для безопасности ветка не протестирована.

### 5.2 🔴 КРИТИЧНО — Titan: «production»-развёртывание с инвертированным профилем безопасности

`docker-compose.yml` — файл, помеченный в первой строке как `(production)` и рекомендованный в README как «Способ 1: Docker (рекомендуется)».

**Включает** (строки 39–48): `ENABLE_CONCEPT_EMERGENCE`, `ENABLE_WORKING_NOTEBOOK`, `ENABLE_CAUSAL_GRAPH`, `ENABLE_EVENT_BUS`, `ENABLE_COGNITIVE_RUNTIME`, `ENABLE_VELUM`, `ENABLE_ESSENCE` — семь исследовательских когнитивных слоёв.

**Не включает ни один из:**

| Флаг | Что остаётся выключенным | Последствие |
|------|--------------------------|-------------|
| `ENABLE_TRUTH_GATE` | эпистемический гейт | факты не проходят проверку истинности |
| `ENABLE_TRUTH_POLICY` | вердикт на пути чтения | нет `allow/gap_notice/reject` |
| `ENABLE_RATE_LIMIT` | token-bucket per-IP | при `ports: "8000:8000"` (0.0.0.0) — нет защиты от исчерпания |
| `ENABLE_RESPONSE_GUARDIAN` | контроль ответов | — |
| `ENABLE_OUTPUT_FAITHFULNESS` | проверка соответствия ответа фактам | — |
| `ENABLE_IMMUTABLE_CORE` | снапшоты неизменяемого ядра | — |
| `ENABLE_OBSERVER` | пассивный мета-монитор | — |

Плюс `docker-compose.yml` не содержит `read_only`, `cap_drop`, `no-new-privileges` или `security_opt`. (Сам `Dockerfile` при этом корректен: multi-stage, `USER velantrim`, `HEALTHCHECK`.)

> 💡 **Суть проблемы:** экспериментальные слои включены, защитные — выключены. Для production-профиля соотношение должно быть строго обратным.

### 5.3 🟠 ВЫСОКО — эпистемическое ядро выключено по умолчанию

`core/feature_config.py`: из 47 флагов **7 включены**, **40 выключены**.

Включены: `write_gate`, `causal_graph`, `domain_tags`, `cognitive_fact`, `cognitive_store`, `cognitive_runtime`, `cross_domain_causal`.

Выключены — в том числе весь эпистемический стек: `truth_gate`, `truth_policy`, `observer`, `graph_expansion`, `task_routing`, `immutable_core`, `response_audit`, `response_guardian`, `output_faithfulness`, `rate_limit`, `circuit_breaker`.

Код честен насчёт причины (`feature_config.py:52–56`):

> *«Temporary scaffolding: canon Definition-of-Done is "strong gates ON by default"; flip this default in a later increment once the eval ruler validates behavior.»*

**Но README.md продвигает эти модули как реализованную ценность** («🛡️ Новая иммунная система», «🚀 Production-ready») без указания, что они выключены.

### 5.4 🟠 ВЫСОКО — TruthGate: 4-я стадия нерабочая во всех допустимых конфигурациях

`core/truth_gate.py:106–130` — параметр `contradiction_detector` принимает три значения:

| Значение | Поведение | Пригодность |
|----------|-----------|-------------|
| `"none"` | **по умолчанию** — стадия обнаружения противоречий пропускается | ⚪ ничего не делает |
| `"naive"` | word-overlap-XOR-negation | 🔴 сам код документирует ложные срабатывания: *«вода кипит при 100°C» / «вода не кипит при 0°C» → false positive*; помечен «только для development» |
| `"nli"` | `raise NotImplementedError` | 🔴 не существует |

То есть обнаружение противоречий — центральная функция «Движка Истины» — недоступно ни в одной production-пригодной конфигурации. Зависимость: интеграция NLI cross-encoder через внешний ATLAS-OS, отложена на «Sprint 2c».

### 5.5 🟠 ВЫСОКО — путь повышения обходит TruthGate (осознанно, но задокументированно)

`core/memory.py:2654–2666` — комментарий разработчика:

> *«this generic ladder-walker is used by call sites outside graduated-promotion/consolidation (world_skills_ingest, CognitiveStore.transition, test fixtures) purely as an ESM-legality helper, so it intentionally still ends its walk with a plain transition_esm() into 'Validated' — NOT validate_and_promote(). Routing every one of those callers through TruthGate is out of scope here.»*

Практическое следствие в `core/world_skills_ingest.py:255`: при `validate=True` (**значение по умолчанию**) каждый распарсенный из markdown факт повышается до `Validated` вызовом `promote_to_validated(by="world_skills_ingest")` — без оценки TruthGate и без проверки доказательств.

Это в точности паттерн, который инвариант №30 Native Kernel запрещает: *«ни одно... предложение не может быть молча повышено до принятого знания»*. Смягчающее обстоятельство — курируемое происхождение корпуса; но архитектурно граница проходит не там, где заявлено.

### 5.6 🟠 ВЫСОКО — расхождение матрицы переходов ESM + отсутствие защиты от дрейфа

`core/memory.py:47–50` утверждает: *«Теперь матрицы идентичны»*. **Проверено программно — это неверно:**

```text
SQL пар: 15   Python пар: 14

В SQL, но не в Python:  ('Observed', 'Observed')
В Python, но не в SQL:  —

IDENTICAL: False
```

Конкретное расхождение **безопасно по направлению**: SQL (`migrations/009_truth_kernel.sql:112`) более разрешающий, Python — строже, поэтому нелегальная запись не проходит.

**Реальный риск — отсутствие теста.** `tests/test_esm.py` проверяет только 3 отдельных элемента (строки 63–71), а не тождество множеств. Их собственный action item #2 требовал именно «тест на идентичность множеств» — он не добавлен. Правка в обратном направлении (Python разрешительнее SQL) даст рантайм-`ABORT` от триггера, и тесты этого не поймают.

### 5.7 🟡 СРЕДНЕ — абстракция хранилища не соблюдается на L0–L2

Асимметрия, определяющая пределы технологической нейтральности Titan:

| Слой | Абстракция | Состояние |
|------|-----------|-----------|
| **L3 (граф)** | `GraphStoreBackend` + `core/storage_facade.py` | ✅ 4 сменных бэкенда: `memory`, `sqlite`, `ladybug`, `neo4j` |
| **L0–L2 (реляционный)** | **отсутствует** | 🔴 **107 прямых вызовов `sqlite3.connect()` в 28 модулях `core/`** |

Худшие концентрации: `embedding_store.py` (12), `entity_resolver.py` (9), `ngram_index.py` (8), `identity_layer.py` (7), `forgetting.py` (7), `conversation_consolidation.py` (7).

**Следствие для канона:** инвариант №12 Native Kernel («SQLite, graph, FTS и векторы — адаптеры, а не архитектура») для Titan выполним только на L3. При 107 точках привязки замена реляционного субстрата невозможна без переписывания 28 модулей.

### 5.8 🟡 СРЕДНЕ — схема БД без единого источника истины

Гибридное управление схемой:

- **12** нумерованных миграций — но нумерация начинается с **008**; миграций 001–007 в репозитории нет

<a name="8"></a>
## 8. ⚠️ Архитектурные риски масштабирования и эволюции

### 8.1 Комбинаторный взрыв конфигураций

47 булевых флагов = 2⁴⁷ теоретических конфигураций. Тестируется практически одна (значения по умолчанию) плюс профиль compose. Флаги не декларируют зависимостей и конфликтов машинно-проверяемым образом. С ростом числа слоёв растёт вероятность конфигурации, которая проходит CI и ломается в развёртывании.

### 8.2 Потолок технологической нейтральности

При **107** прямых `sqlite3.connect()` в **28** модулях замена реляционного субстрата не является операцией смены адаптера — это рефакторинг 28 модулей. Заявленная цель Native Kernel («портируемость между профилями реализации») для L0–L2 Titan сейчас недостижима без предварительной работы.

### 8.3 Хрупкость сложности выборки

`ARCHITECTURE.md:224–235` (Native Kernel) прямо фиксирует: желаемая стоимость сборки снапшота ≈ `O(E + L + C)`, но полный конвейер отбора **не гарантированно линеен**, так как greedy-ablation может приближаться к `O(K²)` по числу активированных кандидатов. `STATUS.md:190–195` добавляет, что широкие запросы во внешнем чекпоинте оставались суперлинейными. Это ограничение архитектуры, а не реализации, и оно проявится на масштабе.

### 8.4 Bus factor и фрагментация источника истины

Три независимых проявления одной проблемы:
1. Native Kernel заблокирован утерянным локальным артефактом
2. `CANONICAL.md` называет каноном локальный Windows-путь и перечисляет ≥8 неверсионированных копий
3. Два «эталона» архитектуры (Ring Zero, Core-3) находятся вне git

Всё это указывает на систему, чья целостность зависит от файловой системы одного человека.

### 8.5 Эпистемический дрейф под нагрузкой продукта

Native Kernel предписывает: никакого молчаливого повышения до принятого знания. Titan уже имеет три задокументированных исключения (`world_skills_ingest`, `CognitiveStore.transition`, тестовые фикстуры) — не из-за небрежности, а из-за практического давления. Без исполняемых fixtures-фикстур для `NK-EPI-008` число таких исключений будет расти монотонно.

### 8.6 Асимметрия стандартов внутри одной организации

Правила Native Kernel (`copilot-instructions.md`) прямо запрещают описывать проект как «production-ready», если доказательства репозитория этого не поддерживают. README Titan содержит раздел «🚀 Production-ready» при 40 из 47 выключенных флагов. Один и тот же владелец применяет два несовместимых эпистемических стандарта. При due diligence это обнаруживается быстро и обесценивает более дисциплинированный репозиторий.

## 10. 💎 Потенциал, ценность и уникальность

### 10.1 Что здесь действительно редкое

**1. Эпистемическая строгость как инженерный артефакт.**
Индустрия AI-памяти конкурирует качеством поиска. Здесь построено нечто другое: система, которая различает *«найдено»*, *«полезно»*, *«часто используется»* и *«обосновано»*, и отказывается их смешивать. Инварианты №5–№7 Native Kernel («история событий ≠ принятая истина», «релевантность отбора ≠ эпистемическая валидность», «полезность исхода ≠ доказательство истины») формулируют различение, которое большинство RAG-систем не делает вовсе.

**2. Восемь утверждений `NK-EPI` — потенциально публикуемый вклад.**
`представление ≠ реальность`, `наблюдение ≠ объяснение`, `преобразование ≠ происхождение`, `неизвестное ≠ ложное`, `текущий предел ≠ универсальная невозможность` — это операционализация философии науки в виде проверяемых утверждений о поведении системы. Прямо релевантно регуляторной повестке EU AI Act (прозрачность, объяснимость, происхождение данных).

**3. Технологическая нейтральность как проверяемое условие, а не лозунг.**
`ARCHITECTURE.md:237–262` определяет контракт портируемости и требует **предъявить эквивалентность** между профилями, а не заявить её. Инвариант №20 честен до конца: *«Технологическая независимость — исследовательская гипотеза, пока не продемонстрирована на нескольких профилях реализации.»*

**4. Работающая реализация GDPR-стирания поверх append-only модели.**
Инвариант №14 фиксирует настоящее противоречие («требования законного удаления не могут быть отменены append-only-дизайном»), а Titan его решает: durable resumable saga для Art. 17 (`erasure_coordinator.py` 2 084 стр. + `erasure_batch_coordinator.py` 1 583 стр., 248 KB тестов), content-free tombstones, редакция PII. Это коммерчески значимый и технически трудный результат.

**5. Local-first по построению.**
`dependencies = []` в `pyproject.toml` — ядро работает на stdlib. Внешние пакеты нужны только опциональным функциям. Для европейского рынка (суверенность данных, отсутствие обязательного облака) это архитектурное преимущество, а не ограничение.

**Инвестиционный тезис в одном абзаце:**

> Это не «ещё одна векторная база с памятью». Это попытка построить *проверяемую эпистемологию* для машинной памяти — с работающей реализацией на 68 000 строк и каноном, который выдержит смену вычислительного субстрата. Технический риск умеренный и понятный. Главный риск не технический, а **репрезентационный**: проект систематически описывает себя неточно в обе стороны, а его самый дисциплинированный трек не имеет ни одного исполняемого артефакта. Оба недостатка устранимы за один квартал и не требуют новых научных идей — только исполнения того, что уже спроектировано.

### 10.3 Соответствие грантовым программам

- **NLnet / NGI Zero** (Европа): local-first, stdlib-ядро, суверенность данных, GDPR-реализация, open source, отсутствие облачной зависимости — попадание близко к идеальному. Требуется английская документация (§9.2 M9).
- **EU Horizon / EIC** (объяснимый AI): `NK-EPI-001…008` + Receipt-семантика + `provenance_chain` напрямую отвечают требованиям прозрачности и трассируемости AI Act.

## 📌 Заключение

Аудит выявил систему, чья **инженерия сильнее её самопрезентации** — редкий и легко исправимый недостаток.

**Три вывода:**

1. ✅ **Инженерия настоящая.** 2 023 зелёных теста, mypy strict на 238 файлах, канарейка-секрет в Docker-CI, обязательный неотключаемый гейт записи, durable GDPR-saga, версионированное каноническое хеширование. Это работа профессионального уровня, и предельно низкое дублирование на 68 000 строк это подтверждает.

2. ⚠️ **Разрыв не в коде, а в двух местах:** между тем, что документы говорят, и тем, что код делает (§7.7); и между каноном и его единственной реализацией (§9.3). Ни то, ни другое не требует новых идей — только исполнения.

3. 🎯 **Ближайший высокоценный шаг — Conformance Bridge (Фаза 2).** Он превращает Native Kernel из прозы в доказательство, даёт Titan внешний критерий корректности, устраняет асимметрию стандартов и создаёт артефакт, который сторонний валидатор может запустить — **без нарушения ни одного гейта и без ожидания утерянного архива**.

> 🔱 Проекту не нужно становиться чем-то другим. Ему нужно точно рассказать, чем он уже является, и соединить две половины, которые он уже построил.
