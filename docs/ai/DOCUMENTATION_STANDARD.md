# 📚 Velantrim Documentation Standard v1

`overview != current state != evidence != history`

- `STRUCTURAL_CHANGE`: review all landing surfaces; update only affected ones.
- `STATE_CHANGE`: refresh stale high-level state claims.
- `EVIDENCE_ONLY`: update evidence/checkpoints without visual churn.

Visual roles: Tree = what exists; Mindmap = concept relations; ASCII = information/authority flow; Table = allowed/forbidden boundaries; Commentary = rationale.

Machine navigation: `project_manifest.json`. Technical state remains in `CURRENT_STATE.md`, `docs/state/project_state.json`, live code, tests and CI.
