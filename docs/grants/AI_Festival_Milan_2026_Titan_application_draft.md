## Short answers

### Problem

When small organizations and non-engineer workers start relying on AI agents for real tasks, those agents write into memory and change state without an inspectable audit trail. Finding an old note that "the purchase was approved" is not proof of current approval. Opaque memory turns AI from a productivity tool into an unaccountable black box, especially for teams that cannot hire a security team.

### Solution

Titan is a research-grade, local-first AI memory and orchestration prototype. It separates recall, provenance, review, and authorized changes, so retrieving information is never treated as permission to trust or act on it. Public GitHub main includes an epistemic state machine for facts, controlled write and promotion gates, hash-linked provenance and audit surfaces, hybrid retrieval, an authenticated FastAPI server and console, and a replaceable LLM layer.

### Stage

Prototype. Runnable local install (venv/uvicorn and Docker Compose), documented test baseline (ruff, mypy, pytest). 0 users, no external audit, unsigned audit chain. Not production-authorized.

### Team

1 person: founder Ruslan Gagiev, Hamburg, Germany. Non-engineer founder directing AI coding assistants; no paid team claimed.

### Innovation / defensibility

Most AI memory products optimize for convenience. Titan inverts the default: retrieval is not evidence, admission is not verification, model output is not trusted state. Language generation never silently becomes authority to mutate memory.

### Business model

No registered company, no revenue. Open source (MIT License). Possible later services around audit hardening, deployment help, and evaluation for agencies, banks, and small teams adopting AI agents. Currently grant-funded applications only, none awarded.
