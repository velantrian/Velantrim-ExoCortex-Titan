| telecom.ops.fiber_splicing | Fiber Optic Splicing — Fusion Technique | METHOD | Сварка (fusion splicing) оптических волокон: концы очищены от оболочки, сколоты под 90° (прецизионный скалыватель, угол <1°), совмещены в сварочном аппарате по сердцевине (core alignment — видеокамера + микромоторы) или по оболочке (cladding alignment, дешевле), электрическая дуга 1700-2000°C за 1-2 секунды сплавляет торец. Затухание на сварке: <0.02-0.05 дБ (хорошо), <0.1 дБ (допустимо), >0.1 дБ — переделать. Защита: термоусадочная гильза (K-wire 60 мм, стальной стержень для прочности). Механический соединитель (mechanical splice): быстрее (30 сек vs 2 мин сварки), но затухание 0.1-0.5 дБ и менее надёжен. OTDR (Optical Time Domain Reflectometer): измеряет длину линии, затухание, местоположение дефектов. | Сварка — стандарт для постоянных соединений (магистральные линии). Механический сплайс — для временных/аварийных (восстановление обрыва ночью, сварщик недоступен). Типичная бригада: 2 человека, 20-50 сварок в день (зависит от волокон в кабеле, 12-144). |
| telecom.ops.ftth_installation | FTTH Installation — Drop Cable to ONT | METHOD | Оптика до квартиры (Fiber To The Home): магистральный кабель → сплиттер (1:32 или 1:64) в распределительной коробке (FDH) → абонентский дроп-кабель (1-2 волокна, pre-connectorized с factory-polished SC/APC коннектором) → оптическая розетка → патч-корд → ONT (Optical Network Terminal). ONT конвертирует оптический сигнал в Ethernet + Wi-Fi + телефонию + IPTV. Приёмка: измерить мощность на ONT (приёмник GPON: −8 to −28 dBm для class B+, −8 to −27 dBm для class C+), OTDR трассировка для документирования. Монтаж в квартире: кабель по плинтусу/кабель-каналу, радиус изгиба >20 мм (меньше — потери на макроизгибе, особенно на длине волны 1550 нм), оптическая розетка с запасом кабеля 1-3 м (для переделки). | Самая частая причина плохого сигнала: загрязнение коннектора. Одна пылинка (1-5 мкм) на торце керамической втулки → потери 1-5 дБ. Обязательная очистка: one-click cleaner (сухая чистка) + инспекция (fiberscope, увеличение 200-400x). |
| telecom.ops.5g_cell_planning | 5G Cell Planning — Site Selection & Parameters | METHOD | Планирование сети 5G: плотность сайтов выше чем 4G (small cells через 200-500 м в urban vs 1-2 км для 4G macro). n78 (3.5 ГГц, 3300-3800 МГц) — основная полоса 5G mid-band (баланс покрытия и ёмкости: 0.5-2 км радиус). mmWave n258/n261 (26/28 ГГц) — сверхскорость (до 4 Гбит/с), но радиус 100-300 м, не проходит через стены/листву. Massive MIMO (64T64R — 64 передающих и приёмных цепей): beamforming (формирование узкого луча на каждого пользователя, 3D beamforming — азимут + elevation). Site acquisition: аренда крыши/столба, backhaul (оптика до сайта — 1-10 Гбит/с), электропитание (до 5-10 кВт на сайт — больше чем 4G). | Плотность сети 5G в 3-5 раз выше 4G по числу сайтов (особенно в городах). Street furniture (фонарные столбы, автобусные остановки) становятся базовыми станциями. Планирование по цифровой 3D-модели города с учётом зданий (ray tracing — симуляция отражений и дифракции луча). |
| telecom.ops.satellite_ground_station | Satellite Ground Station — TT&C Operations | METHOD | Telemetry, Tracking & Command (TT&C): станция слежения и управления спутником. Антенна: parabolic dish (3-13 м для LEO, до 30 м для GEO/deep space), tracking system (программное наведение по эфемеридам + autotrack по уровню сигнала). Частоты: S-band (2-4 ГГц, TT&C), X-band (7-8 ГГц, данные), Ka-band (26-40 ГГц, высокоскоростные данные). Pass: видимый пролёт спутника над станцией (для LEO — 5-15 минут, 5-15 passes/day/спутник). Во время пролёта: ranging (измерение расстояния по задержке сигнала), telemetry приём (состояние подсистем: питание, температура, ориентация), command отправка (коррекция орбиты, загрузка ПО). Link budget: EIRP (Effective Isotropic Radiated Power), free space path loss (растёт с квадратом расстояния и частоты), G/T (добротность приёмной системы), запас на fading. | LEO constellations (Starlink, OneWeb) создали потребность в десятках ground stations по миру. Автоматизация: одна станция может обслуживать сотни спутников по расписанию (scheduler), без человека (lights-out operations). |
| telecom.ops.noc_monitoring | NOC — Network Operations Center Monitoring | METHOD | Network Operations Center: круглосуточный мониторинг сети. Инструменты: NMS (Network Management System — SolarWinds, PRTG, Zabbix) собирает SNMP-ловушки, ICMP ping, NetFlow/sFlow, syslog. Dashboard: карта сети с цветовой индикацией (зелёный OK, жёлтый degraded, красный down). Alarms: severity levels (Critical — сеть не работает, Major — деградация, Minor — единичный инцидент, Warning — приближение к порогу). Эскалация: L1 (first-line — диагностика, перезагрузка, ticket в L2 если не решено за 15-30 мин), L2 (инженеры — глубокая диагностика, удалённое исправление), L3 (вендор / R&D — баги оборудования). SLA: доступность 99.9% (8.7 ч downtime/год), 99.99% (52 мин), 99.999% (5.25 мин — carrier grade). MTTR (Mean Time To Repair): целевой <4 часов. Post-mortem после каждого Critical: Root Cause Analysis. | NOC — нервный центр. Alarm fatigue: слишком много non-actionable alarms → инженеры игнорируют → пропускают реальную аварию. Решение: alarm correlation (одна причина → десятки симптомов, группировка в один root-cause alarm), AI/ML anomaly detection (обнаруживает отклонение до crossing threshold). |
| telecom.ops.helpdesk_tier1 | IT Helpdesk — Tier 1 Operations | METHOD | Первая линия поддержки (service desk). Процесс: 1) Contact (звонок/чат/email/портал самообслуживания), 2) Ticket creation (категория, приоритет, описание, SLA clock starts), 3) Triage — сбор симптомов, базовые вопросы («перезагружали?», «кабель подключён?»), поиск по knowledge base (известная проблема → решение). 4) Resolution (45-65% всех обращений решается на L1) или Escalation (передача L2, ticket не закрывается — L1 остаётся владельцем до закрытия). 5) Verification (перезвонить клиенту через 24-48 часов — действительно ли решено?). KPI: FCR (First Call Resolution — решено при первом контакте, цель 65-70%), AHT (Average Handle Time — 5-10 мин), ASA (Average Speed of Answer — <30 сек для critical), Abandonment rate (<5%), CSAT (Customer Satisfaction >90%). | Knowledge Base — главный инструмент L1: 80% обращений повторяемы, решение должно быть документировано. Если L1 не может найти KB article → создать draft для L2/L3 (continuous improvement). Remote desktop tools: TeamViewer, AnyDesk, SCCM для удалённого решения. |
| telecom.ops.data_center_cooling | Data Center — Cooling Systems Operation | METHOD | Отвод тепла от серверов. Hot aisle / Cold aisle containment: стойки чередуются передними сторонами (холодный коридор, 18-22°C) и задними (горячий коридор, 35-45°C). Изоляция коридоров (пластиковые шторы/панели) предотвращает смешивание воздуха. CRAC/CRAH (Computer Room Air Conditioner/Handler): охлаждённый воздух подаётся под фальшпол (plenum) → через перфорированные плитки в холодные коридоры → серверы → горячий воздух собирается над потолком или в горячем коридоре → возврат в CRAC. Free cooling (фрикулинг): при наружной температуре <10-15°C чиллер отключается, воздух с улицы или градирни напрямую охлаждает (с фильтрацией). PUE (Power Usage Effectiveness): общая энергия ЦОД / энергия IT-оборудования. Мировой benchmark: PUE 1.5-2.0 (средний), 1.1-1.2 (best practice — Google/Facebook). PUE 1.1 means: на 1 МВт IT нагрузка добавляется 0.1 МВт на охлаждение/освещение/потери UPS. | Free cooling снижает PUE: Google (Hamina, Финляндия) PUE 1.09 на морской воде. ASHRAE расширил допустимый диапазон температуры в стойке до 18-27°C (раньше 20-22), что позволяет больше часов free cooling. |
| telecom.ops.cybersecurity_soc | SOC — Security Operations Center | METHOD | Security Operations Center: мониторинг и реагирование на киберугрозы. SIEM (Security Information and Event Management — Splunk, QRadar, Azure Sentinel): агрегирует логи со всех систем (firewall, серверы, endpoints, IDS/IPS), коррелирует события, выдаёт алерты. Triage: аналитик L1 просматривает алерт (false positive? true positive? severity?), L2 — investigation (контекст, scope, impact), L3 — threat hunting (проактивный поиск угроз, не попавших в алерты). Incident Response: NIST SP 800-61 framework: Preparation → Detection & Analysis → Containment (изоляция заражённых хостов) → Eradication (удаление malware, закрытие уязвимости) → Recovery (восстановление из backup) → Post-Incident Activity (lessons learned). MTTD (Mean Time to Detect): целевой <1 часа (реально 100-200 дней для сложных атак по отчётам Mandiant). MTTR (Mean Time to Respond): <4 часов. | SOC — война с false positives (99% алертов). SOAR (Security Orchestration, Automation and Response): автоматические playbooks (алерт на phishing → автоматически извлечь URL, проверить репутацию, удалить email из почтовых ящиков всех получателей). |
