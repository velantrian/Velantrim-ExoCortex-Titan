# BATCH 589: Engineering — Cybersecurity, Telecom & Electronics

**KnowledgeUnits:** 50
**Namespace:** `cs.cybersecurity.*` `engineering.telecom.*` `engineering.electronics_advanced.*`
**Scope:** threat_modeling, penetration_testing, zero_trust, incident_response, digital_forensics, 5g, ofdm, mimo, signal_processing, embedded_systems, fpga.

| ID | KnowledgeUnit | Тип | Суть | Практический смысл |
|---|---|---|---|---|
| cs.cybersecurity.threat_modeling | Threat Modeling — STRIDE | METHOD | Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege. Анализ каждого компонента системы (DFD — data flow diagram) на предмет каждой угрозы. Microsoft, 1999. | PASTA, Trike, Attack Trees, MITRE ATT&CK (тактики, техники, процедуры — матрица знаний). Threat modeling должен предшествовать разработке, не после. |
| cs.cybersecurity.penetration_testing | Penetration Testing Methodology | METHOD | Разведка (OSINT, сканирование портов Nmap, перечисление сервисов) → идентификация уязвимостей (Nessus, ручной анализ) → эксплуатация (Metasploit, ручные эксплойты) → пост-эксплуатация (повышение привилегий, lateral movement) → отчёт. Этичное: согласованные рамки, rules of engagement. | Красная команда (red team) vs синяя (blue team) vs фиолетовая (purple — совместная). Типы: black-box, white-box, grey-box. OWASP Top 10 для веба. |
| cs.cybersecurity.zero_trust | Zero Trust Architecture (ZTA) | MODEL | «Никогда не доверяй, всегда проверяй». Микропериметр: каждый ресурс защищён индивидуально. IAM (управление доступом), MFA обязательна, непрерывная верификация, минимум привилегий (JIT — just-in-time), микросегментация сети. NIST SP 800-207. | Периметр сети больше не существует (облака, удалённая работа, SaaS). BeyondCorp (Google) — реализация Zero Trust. |
| cs.cybersecurity.incident_response | Incident Response — NIST SP 800-61 | METHOD | Preparation → Detection & Analysis → Containment (изолировать, чтобы не распространялось), Eradication (удаление причины — вредонос, закрытие уязвимости) → Recovery → Post-Incident Activity (lessons learned, обновление планов). | Первое: не паниковать, не выключать скомпрометированную машину (потеря криминалистических данных в памяти!). Изолировать, создать образ памяти и диска. |
| cs.cybersecurity.digital_forensics | Digital Forensics — Order of Volatility | METHOD | Регистры CPU/кэш (нс) → память RAM (мс) → сетевые соединения, процессы → временные файлы → диски, удалённые логи. Сбор по убыванию волатильности. Целостность: хеш-суммы образов (SHA-256), write blockers (аппаратная блокировка записи). | Цепочка хранения (chain of custody): кто, когда, где, что делал с доказательством — критично для суда. |
| engineering.telecom.ofdm | OFDM — Orthogonal Frequency Division Multiplexing | INVARIANT | Разделение спектра на множество узкополосных поднесущих, ортогональных друг другу (пик одной совпадает с нулями других). Cyclic prefix (копия конца символа в начало) для борьбы с межсимвольной интерференцией. IFFT/FFT реализация. | 4G LTE, 5G, Wi-Fi (802.11a/g/n/ac/ax), DVB-T, ADSL. Устойчивость к многолучевому распространению. |
| engineering.telecom.mimo | MIMO (Multiple-Input Multiple-Output) | METHOD | Несколько антенн на передаче и приёме. Spatial multiplexing: разные потоки данных → независимые пространственные каналы → умножение пропускной способности. Beamforming: фазирование сигнала для направления луча на конкретного пользователя. Massive MIMO (5G: 64T64R и более). | Спектральная эффективность ↑ пропорционально min(N_TX, N_RX). Предварительное кодирование (precoding) на основе оценки канала (CSI). MU-MIMO (многопользовательское, несколько терминалов одновременно). |
| engineering.telecom.shannon_hartley | Shannon-Hartley Theorem | INVARIANT | C = B·log₂(1 + S/N) [бит/с]. Предел спектральной эффективности (C/B) при данной SNR. Шеннон (1948). Приближение к пределу: Turbo-коды (Berrou, 1993), LDPC (Gallager, 1960, реализованы в 2000-х), Polar-коды (Arıkan, 2009). | 5G: LDPC для данных, Polar для управления. Кодирование с коррекцией ошибок (FEC) приближает к пределу Шеннона на доли дБ. |
| engineering.telecom.5g_nr | 5G New Radio (NR) | RECORD | Частоты: FR1 (<6 ГГц) и FR2 (mmWave, >24 ГГц, до 52.6 ГГц и далее). Нумерологии (разное расстояние между поднесущими: 15/30/60/120 кГц). eMBB (сверхширокополосный), URLLC (сверхнадёжный с малой задержкой <1 мс), mMTC (massive IoT). | 5G Core (5GC): сервис-ориентированная архитектура (SBA), network slicing (логические сети для разных сервисов). |
| engineering.electronics_advanced.fpga | FPGA — Field Programmable Gate Array | METHOD | Массив конфигурируемых логических блоков (LUT — таблицы истинности, D-триггеры) + межсоединения + DSP блоки (умножители/аккумуляторы) + Block RAM. Конфигурация SRAM-based (Xilinx/AMD, Altera/Intel) или flash-based (Microchip). HDL: Verilog, VHDL. HLS (C++ → RTL). | Прототипирование ASIC, акселерация алгоритмов (низкая задержка vs GPU), программно-определяемое радио (SDR), trading, аэрокосмос (радиационно-стойкие FPGA). |
| engineering.electronics_advanced.embedded_systems | Embedded Systems — MCU & RTOS | METHOD | Микроконтроллер (CPU + RAM + Flash + периферия (GPIO, UART, I²C, SPI, АЦП, ШИМ, таймеры). RTOS (FreeRTOS, Zephyr): детерминированное планирование (вытесняющее), приоритеты, семафоры, очереди сообщений, минимизация jitter. Watchdog timer (защита от зависания). | ARM Cortex-M (M0-M7) — доминирует на рынке MCU. Энергоэффективность критична (годы от батарейки для IoT). Обновление по воздуху (OTA firmware update). |
