| ID | KnowledgeUnit | Тип | Суть | Практический смысл |
|---|---|---|---|---|
| cs.graphics.rasterization | Rasterization Pipeline | INVARIANT | Вершинный шейдер (трансформация в clip space) → растеризация (треугольники → фрагменты) → фрагментный шейдер (цвет каждого пикселя, текстуры, освещение) → тест глубины/стенсила/альфа → blending. OpenGL, Vulkan. | Реального времени (>30 FPS → для игр). Z-buffer (глубина). MSAA (мультисэмплинг) сглаживание краёв. |
| cs.graphics.ray_tracing | Ray Tracing — Rendering Equation | METHOD | Кадзия (1986): L_o(x,ω) = L_e(x,ω) + ∫ f_r(x,ω',ω)·L_i(x,ω')·(ω'·n) dω'. Трассировка лучей от камеры. Тени, отражения, преломления, ambient occlusion — естественно, но дороже растеризации. | Monte Carlo path tracing: семплирование лучей → шум → denoising (NVIDIA OptiX AI). RTX (аппаратное ускорение ray tracing с Turing 2018). |
| cs.graphics.bvh | Bounding Volume Hierarchy (BVH) | METHOD | Дерево ограничивающих объёмов: сцена упаковывается в иерархию AABB (axis-aligned bounding boxes). Луч тестируется: пропуск целых ветвей → логарифмическая сложность. SAH (Surface Area Heuristic) для оптимального разбиения. | Критично для производительности как офлайн-рендеринга, так и RTX. Обновление BVH для динамических сцен (анимация). |
| cs.graphics.brdf | BRDF — Bidirectional Reflectance Distribution | INVARIANT | f_r(ω_i, ω_o) — доля света, приходящего с направления ω_i и отражающегося в ω_o. Свойства: взаимность (Гельмгольц), сохранение энергии. Модели: Lambert (диффузное, константа), Phong/Blinn-Phong (блик), Cook-Torrance (микрогранник, физически-корректный: Fresnel + геометрическое затенение + распределение нормалей). | Disney Principled BSDF (2012): единая модель с интуитивными параметрами (metallic, roughness, subsurface). Стандарт в индустрии. |
| cs.graphics.pbr | Physically Based Rendering (PBR) | METHOD | Энергетически консервативно, metalness/roughness workflow. Fresnel (Шлик): F = F₀ + (1−F₀)(1−cosθ)⁵. F₀ — отражательная способность при нормальном падении. IBL (image-based lighting): HDR карта окружения как источник света. | Unreal Engine 4+, Unity HDRP. Консистентное освещение между разными объектами. |
| cs.graphics.subsurface_scattering | Subsurface Scattering (SSS) | PROCESS | Свет проникает в полупрозрачный материал (кожа, мрамор, воск, молоко), рассеивается внутри и выходит в другой точке. BSSRDF (двунаправленная функция рассеяния от поверхности). | Кожа выглядит пластиковой без SSS. Метод: экранное пространство (Burley, separable), пред-интегрированное. |
| cs.parallel.amdahls_law | Amdahl's Law — Scaling Limits | INVARIANT | S = 1/((1−P) + P/N). Максимальное ускорение при бесконечных процессорах: S_max = 1/(1−P). Если 10% последовательного кода → S_max = 10. Закон Густафсона: с ростом N растёт и размер задачи → S = N − α(N−1). | Фундаментальное ограничение. Практически: слабое масштабирование (Gustafson) оптимистичнее для науки (увеличиваем сетку). |
| cs.parallel.cuda_model | CUDA Programming Model | METHOD | Иерархия: Grid → Blocks (разделяемая память) → Threads (регистры). Warp (32 потока SIMD). Ключевые аспекты: коалесцированный доступ к глобальной памяти (соседние потоки → соседние адреса), банк-конфликты разделяемой памяти, occupancy. | Пропускная способность HBM (A100 80GB: 2 TB/s). Tensor Cores — матричное умножение FP16/BF16/INT8. |
| cs.parallel.mpi_openmp | MPI & OpenMP — Distributed & Shared | METHOD | MPI (Message Passing Interface, распределённая память): send/recv, broadcast, reduce, scatter/gather. OpenMP (общая память): #pragma omp parallel for. Hybrid: MPI между узлами + OpenMP внутри узла. | Суперкомпьютеры Top500: Fugaku (A64FX ARM), Frontier (AMD EPYC + MI250X GPU). HPL (LINPACK) бенчмарк. |
| cs.parallel.mapreduce | MapReduce & Hadoop/Spark | METHOD | Map: функция к каждому элементу → (key, value). Shuffle: группировка по ключу. Reduce: агрегация значений по ключу. Устойчивость к отказам (перезапуск упавшей задачи). Spark: in-memory, DAG (ускорение over Hadoop MapReduce disk-based). | Word count — «Hello World». Распределённая обработка терабайт логов, данных. Уступил место ML-фреймворкам (PyTorch distributed). |
| cs.robotics.dh_parameters | Denavit-Hartenberg (DH) Parameters | METHOD | 4 параметра описывают кинематику робота-манипулятора: a (длина звена), α (скручивание), d (смещение), θ (угол шарнира). 4×4 матрицы однородного преобразования. Прямая кинематика: перемножение Tᵢ → положение TCP (tool center point). | Обратная кинематика: аналитическая (ограниченные конфигурации) или численная (Jacobian pseudoinverse — iterative). Сингулярности (потеря 1+ степеней свободы). |
| cs.robotics.slam | SLAM — Simultaneous Localization and Mapping | METHOD | Робот строит карту и определяет своё положение в ней одновременно. EKF-SLAM, FastSLAM (particle filter). Современные: graph-based (узлы=позы, рёбра=ограничения/measurements, оптимизация pose graph). ORB-SLAM3, Cartographer (Google). LiDAR (LIO-SAM), visual (V-SLAM). | Петлевое замыкание (loop closure): распознал место → корректирует накопившийся дрейф. Критично для автономных автомобилей, дронов, пылесосов. |
| cs.robotics.path_planning_a_star | Path Planning — A* to RRT* | METHOD | A* (сетка, оптимален). RRT (Rapidly-exploring Random Tree) — probabilistic, эффективен в высокоразмерных пространствах (манипулятор 7 DOF). RRT* (Sertac Karaman, 2011): асимптотически оптимален. PRM (Probabilistic Roadmap) — многозапросный. | Конфигурационное пространство (C-space). Проверка коллизий (convex decomposition, GJK). Траекторная оптимизация (CHOMP, TrajOpt). |
