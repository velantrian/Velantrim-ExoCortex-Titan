# BATCH 802: Information Security — Enterprise Architecture

**KnowledgeUnits:** 50
**Namespace:** `infosec.ops.*`
**Scope:** risk_management, identity_access, DLP, endpoint_security, cloud_security, incident_response, GRC, encryption, NIST_framework

| ID | KnowledgeUnit | Тип | Суть | Практический смысл |
|---|---|---|---|---|
| infosec.ops.nist_csf | NIST Cybersecurity Framework | METHOD | NIST CSF (2.0): 6 функций — Govern, Identify, Protect, Detect, Respond, Recover. Govern: политики и управление рисками. Identify: asset management + risk assessment. Protect: access control + training. Detect: continuous monitoring. Respond: response planning. Recover: recovery planning. | CSF 2.0 добавляет «Govern» как 6-ю функцию (governance across all other functions). |
| infosec.ops.risk_assessment | Information Security Risk Assessment | METHOD | Оценка риска ИБ: Risk = Threat × Vulnerability × Impact. Методологии: FAIR (Factor Analysis of Information Risk), OCTAVE, ISO 27005. Qualitative vs Quantitative assessment. ALE (Annualized Loss Expectancy) = ARO × SLE. ASSE: Asset value + Threat + Vulnerability + Countermeasure. | FAIR: единственная международно-признанная количественная модель рисков ИБ. |
| infosec.ops.iam_lifecycle | IAM — Identity Lifecycle | METHOD | Управление идентификацией и доступом (IAM): Join (предоставление), Move (изменение ролей), Leave (отзыв). JIT (Just-in-Time Access): доступ только когда нужен. PAM (Privileged Access Management): управление привилегированными. RBAC (Role-Based) vs ABAC (Attribute-Based). Orphan accounts: устаревшие аккаунты = риск. | Quarterly access review: проверка и подтверждение прав доступа. |
| infosec.ops.data_loss_prevention | DLP — Content Inspection | METHOD | Предотвращение утечек данных (DLP): Endpoint DLP: блокировка USB, clipboard, screenshots. Network DLP: инспекция Email, Web, SMTP. Cloud DLP (CASB). Policy: тип данных (PII, PCI, PHI) + контекст. Fingerprinting (exact match) vs RegEx. Incidents queue: тriage. | «Shadow IT» облачное хранилище = крупнейший источник утечек данных (не взломы). |
| infosec.ops.zero_trust_principles | Zero Trust — Implementation | METHOD | Реализация Zero Trust: Microsegmentation: разделить сети на зоны. Identity as perimeter: MFA + conditional access. Device posture: антивирус, patching, compliance. App-level access (ZTNA): заменяет VPN. Continuous verification: не «однажды и навсегда». Logs + analytics: поведенческое обнаружение. | NIST SP 800-207: Zero Trust Architecture reference document. |
| infosec.ops.secure_sdlc | Secure SDLC — Stages | METHOD | Безопасная разработка (SSDLC): Требования: security requirements analysis. Дизайн: Threat modeling (STRIDE, PASTA). Разработка: SAST, code review. Тестирование: DAST, pentesting. Деплой: секреты в vault, конфигурации hardened. Эксплуатация: runtime protection (RASP). | SAST vs DAST: SAST = анализ кода (раньше), DAST = тест в runtime (позже). |
| infosec.ops.encryption_in_transit | Encryption — In Transit & At Rest | METHOD | Шифрование данных: В транзите: TLS 1.3 минимум. Certificate pinning. HSTS. MTLS (mutual TLS) для service-to-service. В покое: AES-256. LUKS (Linux Full Disk Encryption). Transparent Data Encryption (TDE) для баз данных. Key Management: HSM (Hardware Security Module), cloud KMS. | Encryption key rotation: минимально ежегодно. Compromised key → re-encrypt all. |
| infosec.ops.patch_management | Patch Management — Prioritization | METHOD | Управление патчами: CVSS (Common Vulnerability Scoring System): 0-10. Critical ≥9, High 7-8.9. Exploit in wild: повышает приоритет. EPSS (Exploit Prediction Scoring System): вероятность активной эксплуатации. SLA: Critical = 24-48 ч, High = 7 дней, Medium = 30 дней. Patch automation (WSUS, SCCM, Ansible). | VPR (Vulnerability Priority Rating) = CVSS + business context + exploit intelligence. |
| infosec.ops.siem_use_cases | SIEM — Use Cases | METHOD | SIEM Use Cases (Splunk, Microsoft Sentinel): Lateral movement detection: внезапный доступ к многим машинам. Impossible travel: login из двух разных стран за короткое время. Mass file deletion/encryption: Ransomware indicator. Brute force: many failed logins. Credential stuffing: login с proxy. | Content packs: pre-built detection rules (Splunk ES, Microsoft Sentinel solutions). |
| infosec.ops.gdpr_compliance | GDPR — Data Protection | METHOD | GDPR (General Data Protection Regulation): правовые основания обработки (6): согласие, контракт, юридическое обязательство, жизненный интерес, публичный интерес, законный интерес. Права субъектов: доступ, исправление, удаление, ограничение, переносимость, возражение. DPO (Data Protection Officer): обязателен для крупных обработчиков. | GDPR штрафы: до 4% оборота или €20 млн (whichever higher). |
| infosec.ops.mfa_types | MFA — Authentication Factors | METHOD | Многофакторная аутентификация: Что знаешь: пароль, PIN. Что имеешь: hardware token (YubiKey), TOTP (Authenticator apps). Кто ты: биометрия (Face ID, fingerprint). Where you are: IP geolocation, network. FIDO2/WebAuthn: phishing-resistant MFA. Push notification: уязвим к MFA fatigue attack. | MFA fatigue attack: spam push notifications → пользователь «случайно» одобряет. MFA bypass. |
| infosec.ops.supply_chain_attack | Supply Chain Security | METHOD | Безопасность цепочки поставок программного обеспечения: SolarWinds (2020): скомпрометированный апдейт → 18 000 организаций. 3CX (2023): аналогично. SBOM (Software Bill of Materials): список всех компонентов. Sigstore: подпись артефактов. Code signing. Dependency confusion attack: приватные vs публичные пакеты. | SLSA (Supply Chain Levels for Software Artifacts): фреймворк защиты. |
| infosec.ops.threat_intelligence | Cyber Threat Intelligence — TLP | METHOD | Cyber Threat Intelligence (CTI): Тактическая: IOCs (indicators of compromise) — IP, hash, domain. Оперативная: TTPs (tactics, techniques, procedures). Стратегическая: actor profiles, trending threats. Traffic Light Protocol (TLP): RED (only receivers), AMBER (limited distribution), GREEN (community), WHITE (public). MITRE ATT&CK: TTP taxonomy. | IOC vs TTP: IOCs expire fast (adversary changes); TTPs = longer-lasting intelligence. |
| infosec.ops.devsecops_scanning | DevSecOps — Secret Scanning | METHOD | Поиск секретов в коде: Hardcoded API keys, passwords, tokens в репозиториях. Tools: TruffleHog, GitLeaks, git-secrets. GitHub Advanced Security: автоматическое обнаружение. Secret rotation: немедленно при обнаружении. HashiCorp Vault: safe secret storage. Pre-commit hooks: предотвращение commit. | Exposed AWS keys в GitHub: среднее время эксплуатации <5 мин (Truffle Security). |
| infosec.ops.forensic_response | Digital Forensics — Incident Response | METHOD | DFIR (Digital Forensics and Incident Response): Memory forensics (Volatility): processes, network connections, injected code. Disk forensics: file recovery, timeline analysis. Log forensics: SIEM correlation. Network forensics: PCAP analysis (Wireshark). Registry forensics (Windows): persistence, lateral movement. Evidence preservation: Hash + chain of custody. | Timeline analysis: построить точную хронологию атаки (malware → lateral movement → exfil). |
| infosec.ops.cloud_iam_aws | Cloud IAM — AWS Policies | METHOD | AWS IAM: IAM Policy: JSON документ (Effect, Action, Resource, Condition). Identity-based vs Resource-based policies. Permission boundaries: ограничение максимального разрешения. Organizations SCPs: account-level control. IAM Roles: для EC2, Lambda, Cross-account. Least privilege: минимально необходимое. | AWS IAM Analyzer: находит overly permissive policies. |
| infosec.ops.pen_test_reporting | Penetration Testing — Report | METHOD | Отчёт по пентесту: Executive Summary: для руководства (бизнес-риски). Technical Findings: каждая уязвимость — описание, severity (CVSS), POC (proof of concept), recommendations. Risk Rating: Critical/High/Medium/Low. Remediation timeline. Retesting plan. RoE (Rules of Engagement) included. | CVSS ≠ business risk: критический CVSS на изолированной системе = низкий бизнес-риск. |
| infosec.ops.network_segmentation | Network Segmentation — Defense | METHOD | Сегментация сети: DMZ (Demilitarized Zone): публичные серверы + firewall изоляция. Micro-segmentation: software-defined (NSX, Cisco ACI). Zero Trust micro-segmentation: east-west traffic controls. VLAN isolation. Firewall rules: default deny. | East-west traffic: lateral movement между серверами внутри = критический вектор. |
| infosec.ops.socii_service_org | SOC 2 — Trust Criteria | METHOD | SOC 2 (Service Organization Control): Trust Service Criteria. Security: наиболее распространённый (обязателен). Availability. Processing Integrity. Confidentiality. Privacy. Type I: дизайн контролей. Type II: оперативная эффективность (6-12 мес период). Auditor: AICPA licensed CPA. | SOC 2 Type II: продаётся как «доказательство безопасности» для enterprise клиентов. |
