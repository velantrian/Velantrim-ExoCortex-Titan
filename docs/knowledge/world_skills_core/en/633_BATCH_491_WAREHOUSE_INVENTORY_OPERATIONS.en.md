# BATCH 491: Warehousing & Inventory — Operations & Management

**Scope:** receiving, putaway, slotting, picking, packing, shipping, WMS, cross_dock, cycle_count, automation, AGV, conveyor, safety

| warehouse.ops.receiving_process | Warehouse Receiving — Inbound Process | PROCESS | Приёмка товара. Предварительно: ASN (Advanced Shipping Notice) от поставщика с детализацией (SKU, количество, номер партии, срок годности). Процесс: 1) Разгрузка (dock door назначена, достаточно места), 2) Проверка целостности упаковки (повреждения? фото), 3) Сверка с ASN (счёт коробок/паллет), 4) Blind receiving (пересчёт реального количества без сверки с ASN — если расхождение → пересчёт, escalation поставщику), 5) Quality inspection (выборочная — AQL стандарт: при 1000 единиц sample 80, accept 2 defects, reject 3), 6) System receipt (внесение в WMS — статус Available), 7) Label printing (SSCC — Serial Shipping Container Code для паллеты, GS1-128 для коробок), 8) Putaway (WMS определяет ячейку). | Расхождения (over/short/damage): discrepancy report поставщику в течение 24-48 часов. Хронические проблемы с поставщиком → vendor scorecard downgrade, может повлиять на procurement. |
| warehouse.ops.putaway_strategies | Putaway Strategies — Fixed vs Dynamic Location | METHOD | Размещение принятого товара. Fixed location: у каждого SKU постоянная ячейка (легко запомнить, но плохое использование пространства если запас колеблется). Dynamic/chaotic: WMS назначает любую свободную ячейку (оптимальное использование объёма). Правила WMS для выбора: ABC-velocity (быстрооборачиваемые ближе к shipping), affinity (часто заказываемые вместе — рядом), weight (тяжёлые внизу), размер (крупногабаритные на нижних ярусах или в bulk зоне), FIFO/FEFO (срок годности). Золотая зона: высота 0.6-1.4 м от пола, ближайшие к shipping dock — manual pick (максимальная производительность). Putaway confirmation: сканирование location barcode подтверждает размещение. | Без WMS: оператор запоминает/угадывает куда положить → потеря места (30%+ неэффективность). С WMS: utilisation 90-95%. Putaway accuracy: 99.5%+ (ложное размещение = потеря товара, заказ не собран). |
| warehouse.ops.order_picking_methods | Order Picking Methods — Discrete, Batch, Wave, Zone | METHOD | Методы комплектации заказов. Discrete (покаждый): отборщик идёт за одним заказом → low productivity, high accuracy (для малого числа заказов). Batch picking: отборщик собирает несколько заказов одновременно (до 6-12), сортирует в отдельные контейнеры → повышение производительности в 2-4 раза за счёт сокращения ходьбы. Zone picking: склад разделён на зоны, каждый отборщик в своей зоне — заказ проходит через зоны (последовательный или параллельный с consolidation на конвейере). Wave picking: заказы группируются в волну (например, все заказы UPS pickup 15:00), отборщики идут маршрутами только для этой волны. Pick-to-voice: гарнитура — система голосом говорит «ячейка 1234, 5 штук», отборщик подтверждает голосом. Cвободные руки, глаза на товаре, безопаснее. | Ключевой KPI: UPH (Units Per Hour) — типично 80-120 для piece pick, 200-400 для case pick. Ошибки (mis-pick) <0.1%. Pick path: S-shape (змейкой), return (возврат в проход после каждого отбора), midpoint (до середины прохода и обратно). |
| warehouse.ops.packing_optimization | Packing — Cartonization & Shipping Prep | METHOD | Упаковка заказа: cartonization алгоритм выбирает коробку(и) нужного размера. 3D bin packing: разместить товары в коробке оптимально (dim weight billing — перевозчик берёт по большему из actual weight и dimensional weight = L×W×H / dim divisor). Заполнение пустот: air pillows, kraft paper, foam-in-place. Void fill <10%. DIM factor: FedEx/UPS divisor 139 (дюймы³/фунт). Упаковочная станция: весы (подтверждение что заказ собран правильно — общий вес заказа ± допустимое расхождение = сумма весов SKU), принтер shipping label, dunnage dispenser. Pack verification: сканирование каждого SKU при укладке в коробку → система подтверждает что заказ полный. Gift wrap, invoice placement, personal note если заказано. | Dim weight оптимизация экономит 10-20% shipping costs. Выбор минимально возможной коробки из ассортимента (10-15 размеров) — cartonization software сравнивает все коробки. |
| warehouse.ops.shipping_dock_management | Shipping Dock — Outbound Operations | PROCESS | Отгрузка. Консолидация: все коробки/паллеты заказа собраны в staging area. Проверка: последний шанс исправить ошибку — weight check, аудит 1-5% заказов (открыть, пересчитать), address label проверка. Dock scheduling: назначение времени для каждого перевозчика (load by 15:00 UPS, 16:00 FedEx, 17:00 LTL). Документация: BOL (Bill of Lading — договор перевозки, юридический документ), packing list, customs invoice для международных. Hazardous materials (DOT hazmat): правильная декларация, упаковка, training персонала. Shipping manifest: передача данных перевозчику (EDI/API) → tracking numbers присвоены → клиент получает shipping confirmation email. KPI: On-Time Shipment >99%, Order Accuracy >99.5%. | LTL (Less-Than-Truckload): товар на паллетах, class по NMFC (National Motor Freight Classification — density, stowability, handling, liability определяют class 50-500, определяет rate). Неправильный class → перевозчик выставляет rebill на сотни-тысячи долларов. |
| warehouse.ops.wms_functionality | WMS — Warehouse Management System Core Functions | METHOD | WMS (Manhattan, Blue Yonder, Oracle, SAP EWM) — мозг склада. Функции: 1) Inventory Management (количество, местоположение, статус — Available/Allocated/Held/Quarantine), 2) Location Management (check digit для верификации, физические размеры ячеек, weight capacity), 3) Task Management (очередь задач для операторов — приоритетная логика: next closest task, FIFO, priority boost для hot orders), 4) Labor Management (измерение производительности каждого оператора — UPH, accuracy — vs engineered standards), 5) Slotting (оптимизация размещения), 6) Replenishment (перемещение из резервного хранения в pick face — по min/max уровням), 7) Shipping (parcel manifest, LTL, TL, документирование). Интеграции: ERP (SAP/Oracle), TMS (Transportation), OMS (Order Management). Mobile: RF guns / Android scanners / wearable. | WMS без правильной конфигурации (bad master data: размеры, вес, capacity) = garbage in, garbage out. Внедрение WMS: 6-18 месяцев, $500K-5M+. Окупаемость: повышение точности с 95% до 99.5%, производительности на 20-40%, снижение labour cost. |
| warehouse.ops.agv_deployment | AGV / AMR — Mobile Robots in Warehousing | METHOD | Автоматизированные управляемые транспортные средства. AGV (Automated Guided Vehicle): следует по фиксированному маршруту (магнитная лента, провода в полу, QR-коды) — требует инфраструктуры. AMR (Autonomous Mobile Robot): навигация по SLAM (одновременная локализация и построение карты — LIDAR + камеры), динамическое построение маршрута (объезд препятствий). Применение: goods-to-person (робот привозит стеллаж к отборщику, Amazon Kiva), pallet transport (перемещение паллет из receiving в putaway), sortation (робот доставляет контейнер в нужный chute), case picking (робот снимает коробки с паллет). Производительность: 200-400 picks/час на goods-to-person станции vs 80-120 для manual picking. Безопасность: sensor fusion (LIDAR, 3D camera, ultrasonic) — зоны: warning (<3 м — замедление), stop (<1.5 м — остановка). AMR fleet manager: ПО координирует весь флот, трафик, зарядку. | AMR ROI: 1-3 года. Снижение ходьбы отборщиков на 60-80%. Быстрее чем конвейер для changing layouts. Интеграция: AMR + WMS через API, задачи назначаются динамически. |
| warehouse.ops.cycle_count_audit | Inventory Accuracy — Cycle Count & Audit Program | METHOD | Поддержание точности остатков. Ежедневный cycle count: WMS генерирует список для счёта (10-50 SKU в день в зависимости от размера склада). Стратегия отбора: random, high-value (ABC-analysis), high-discrepancy history, recent picks (считай после отбора), empty locations (подтверждение что ячейка действительно пуста). Процесс: counter сканирует location → сканирует SKU → вводит количество → система сравнивает с book inventory → расхождение > tolerance? → recount. Исследование расхождений: +/- adjustments записаны с reason code (damage, mis-pick, receiving error, theft, system error). Тренд: рост расхождений = проблема с процессом (не с персоналом). KPI: IRA (Inventory Record Accuracy) = 1 - (Σ|book−actual|)/Σbook, цель >99%. Frequency: A-items еженедельно, B-items monthly, C-items quarterly. Wall-to-wall (полная инвентаризация) раз в год (или не нужна если cycle count покрывает все SKU за год). | Главная причина низкой точности: receiving error (приняли не то количество, а потом все последующие транзакции идут с этой ошибкой). Поэтому receiving — процесс №1 для контроля точности. |
| warehouse.ops.replenishment_kanban | Replenishment — From Reserve to Pick Face | METHOD | Пополнение pick face из резервного хранения. Триггеры: min/max (как только остаток в pick face падает ниже min → задача на пополнение), demand-driven (WMS знает будущие заказы и предварительно пополняет), visual (двухячеечная система: два контейнера, когда один пуст — оператор ставит его в зону пополнения). Расчёт размера пополнения: достаточно для покрытия спроса на время пополнения + смену (lead time replenishment = днём 1-2 часа, ночью быстрее). Task interleaving: после завершения отбора система направляет оператора на пополнение (не возвращаться пустым, если по пути). Replenishment priority: если pick face пуст и заказы ждут → немедленное пополнение с priority boost. | Пустой pick face = нулевая производительность отборщика (пропускает SKU, машет руками). Safety stock в pick face должен быть minimизирован (занимает место), но не давать пустого. |
| warehouse.ops.cross_dock_execution | Cross-Docking — Execution & Floors | PROCESS | Исполнение кросс-докинга. Типичный floor plan: inbound dock → sortation area → outbound dock. Flow: inbound truck разгружается → each pallet/case scanned, WMS определяет outbound lane (направление) → conveyor или pallet jack к соответствующей outbound staging lane → outbound truck загружается. Sortation: pop-up wheel sorter, sliding shoe sorter, tilt tray для мелких items. Time window: 2-4 часа от въезда до выезда (дольше = это уже склад, не кросс-док). Pre-distribution: товар приходит с уже назначенным customer/PO → сортировка по outbound маршрутам. Post-distribution: товар без назначения → система определяет как распределить на основе спроса магазинов. Преимущества: исключение хранения, снижение инвентаря, ускорение поставок на 24-48 часов. | Кросс-док требует синхронизации: inbound и outbound расписания должны быть согласованы. Если inbound опаздывает → outbound уходит пустым или неполным (service level страдает). Управление dock doors: critical constraint (на каждый inbound должна быть outbound door, и наоборот). |
