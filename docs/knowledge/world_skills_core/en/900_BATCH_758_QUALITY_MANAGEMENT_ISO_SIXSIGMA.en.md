# BATCH 758: Quality Management — ISO & Six Sigma

**KnowledgeUnits:** 50
**Namespace:** `qualitymgmt.ops.*`
**Scope:** ISO9001, IATF16949, six_sigma, DMAIC, SPC, FMEA, control_charts, PPAP, MSA, GR&R

| ID | KnowledgeUnit | Тип | Суть | Практический смысл |
|---|---|---|---|---|
| qualitymgmt.ops.iso9001_context | ISO 9001:2015 — Key Changes | METHOD | ISO 9001:2015 основные изменения от 2008: Context of the organization (Clause 4). Risk-based thinking (Risk Management throughout). Leadership emphasis (больший фокус Top Management). Knowledge management. Нет обязательного Quality Manual. Process approach усилен. High Level Structure (HLS): совместим с другими ISO стандартами. | PDCA: Plan-Do-Check-Act = основа ISO 9001. |
| qualitymgmt.ops.sipoc_process_map | SIPOC — Process Mapping | METHOD | SIPOC: Suppliers, Inputs, Process, Outputs, Customers. Инструмент для определения границ процесса. Process steps: 4-7 на высоком уровне. Customers: внутренние + внешние. Входные требования и выходные требования. Value Stream Map (VSM): более детальный. | SIPOC первоначальный шаг в DMAIC Define фазе. |
| qualitymgmt.ops.dmaic_phases | DMAIC — Six Sigma Methodology | METHOD | DMAIC (Define, Measure, Analyze, Improve, Control): Define: проблема, CTQ, голос клиента (VOC). Measure: текущая производительность (baseline), Measurement System Analysis. Analyze: Root Cause Analysis, Fishbone, 5 Why. Improve: Generate solutions, pilot test. Control: Control Plan, SPC, Process Documentation. | DFSS (Design for Six Sigma): DMADV для новых продуктов/процессов. |
| qualitymgmt.ops.spc_control_charts | SPC — Control Chart Selection | METHOD | Статистическое управление процессом (SPC): Xbar-R chart: для малых подгрупп (n<10), непрерывные данные. Xbar-S chart: для больших подгрупп. I-MR chart: для индивидуальных наблюдений. P chart: доля дефектов (p). Np chart: количество дефектов. C chart: дефекты на единицу (постоянный объём). U chart: дефекты на единицу (переменный). | 8 Nelson rules: специальные причины в контрольных картах. |
| qualitymgmt.ops.process_capability | Process Capability — Cp Cpk | METHOD | Возможности процесса: Cp = (USL - LSL) / (6σ). Cpk = min[(USL - μ) / (3σ), (μ - LSL) / (3σ)]. Cp ≥ 1.33 (target). Cp = Cpk: центрированный процесс. Pp, Ppk: долгосрочный (total sigma). Sigma Level: 6σ = 3.4 DPMO (с 1.5σ shift). Process Capability Study: ≥50 точек стабильного процесса. | Cp vs Cpk: Cp = ширина допуска. Cpk = с учётом центрирования. |
| qualitymgmt.ops.fmea_design | FMEA — Risk Priority Number | METHOD | FMEA (Failure Mode and Effects Analysis): для каждого потенциального вида отказа. S = Severity (влияние, 1-10). O = Occurrence (вероятность, 1-10). D = Detection (способность обнаружения, 1-10). RPN = S × O × D. Высокий RPN → приоритизировать действие. Design FMEA (DFMEA) vs Process FMEA (PFMEA). AIAG-VDA FMEA 2019: новый стандарт. | AIAG-VDA 2019: AP (Action Priority) вместо RPN threshold. |
| qualitymgmt.ops.gage_repeatability | Gage R&R — MSA | METHOD | Анализ измерительных систем (MSA): Gage R&R: Repeatability (оборудование) + Reproducibility (оператор). GRR % = √(Var_GRR) / Study Variation × 100%. <10% = excellent. 10-30% = marginal (возможно приемлемо). >30% = unacceptable. Number of studies: min 10 части × 3 операторов × 2 повторения. | Если GRR > 30%: измерение ненадёжно → сложно управлять процессом. |
| qualitymgmt.ops.ppap_levels | PPAP — Submission Levels | METHOD | Production Part Approval Process (PPAP, AIAG): уровни 1-5. Level 1: Warrant only. Level 2: Warrant + limited samples. Level 3 (стандартный): Warrant + supporting data. Level 4: customer specific. Level 5: полный пакет у supplier. 18 элементов PPAP: Design records, Engineering Change, PFMEA, Control Plan, MSA, Initial Process Studies, qualified lab docs, etc. | PPAP не утверждён → нельзя отгружать серийную продукцию. |
| qualitymgmt.ops.control_plan | Control Plan — Documentation | METHOD | Контрольный план: определяет контроль входных параметров + параметров процесса + выходных. Columns: Process Step, Characteristic, Spec, Measurement Method, Frequency, Sample Size, Control Method, Reaction Plan. Pre-launch vs Production. Связан с PFMEA (same characteristics). Реакционный план: что делать при выходе за пределы. | Control Plan = обязательный PPAP элемент. |
| qualitymgmt.ops.8d_problem_solving | 8D — Problem Solving | METHOD | Метод 8D (Ford): D1 Team Formation. D2 Problem Description. D3 Interim Containment Action (ICA). D4 Root Cause Analysis. D5 Permanent Corrective Action (PCA). D6 Implementation & Validation. D7 Prevent Recurrence. D8 Recognize Team. Customer требует 8D отчёт при nonconformance. | «Permanent Corrective Action» vs «Interim»: ICA = остановить кровотечение, PCA = устранить причину. |
| qualitymgmt.ops.lean_five_s | Lean — 5S Methodology | METHOD | Метод 5S: Sort (Сортировка — удалить ненужное). Set in Order (Систематизация — «место для всего»). Shine (Содержание в чистоте). Standardize (Стандартизация — документировать). Sustain (Совершенствование — аудит, maintenance). Shadow boards (хранение инструментов). 5S + Safety = 6S. | 5S: basis для Lean Manufacturing (без порядка — нет контроля). |
| qualitymgmt.ops.statistical_sampling | Sampling — AQL | METHOD | Приёмочный уровень качества (AQL): ISO 2859-1 (MIL-STD-1916): уровень AQL = max допустимый % дефектных. Sample size: по inspection level + lot size. Normal, Tightened, Reduced sampling. Operating Characteristic (OC) curve: вероятность принятия vs % дефектов. Critical/Major/Minor: разные AQL. | AQL 1.0 для критических: 1 дефект из 100 максимально приемлем. |
| qualitymgmt.ops.voc_quality_function | VOC — Quality Function Deployment | METHOD | Голос клиента (VOC): VOC → QFD (House of Quality). Whats vs Hows. Customer requirements → Technical Requirements. Correlation matrix: отношения между характеристиками. Competitive benchmarking. Weighted importance. Kano model: Must-be, One-dimensional, Attractive (delight). | Kano: «Must-be» unsatisfied → huge dissatisfaction. «Delighter» → unexpected satisfaction. |
| qualitymgmt.ops.poka_yoke | Poka-Yoke — Error Proofing | METHOD | Защита от ошибок (Poka-Yoke, Shingo): не полагаться на человека. Types: Contact (shape matching), Warning (alert), Control (stops process). Levels: Mistake Elimination → Warning → Detection → Mitigation. Examples: USB только в одном направлении, guided connectors, counters on assembly. 100% inspection vs prevention. | Poka-yoke > statistical sampling: предотвращение лучше обнаружения. |
| qualitymgmt.ops.isoiatf16949 | IATF 16949 — Automotive Quality | METHOD | IATF 16949:2016 (ISO/TS 16949 predecessor): автомобильная промышленность дополняет ISO 9001:2015. Customer-specific requirements (CSR): OEM добавляет свои требования. Embedded requirements (из старого Core Tools): APQP, PPAP, FMEA, SPC, MSA. Warranty/warranty analysis. Laboratory requirements. Product safety requirements. | Tier 1 supplier: должен быть IATF-сертифицирован для большинства OEM. |
| qualitymgmt.ops.six_sigma_belt_levels | Six Sigma Belts — Roles | METHOD | Структура шести сигм: Yellow Belt: базовые знания. Green Belt: реализует проекты (под руководством BB). Black Belt (BB): полноценный проект менеджер и статистик. Master Black Belt (MBB): учит, консультирует, развивает программу. Champion: руководитель, продвигает программу. ASQ Certification: профессиональный стандарт. | GE «Work-Out»: BB требуется каждые 2 года cycle time reduction. |
| qualitymgmt.ops.rca_fishbone | Root Cause Analysis — Ishikawa | METHOD | Диаграмма Исикавы (Fishbone): 6M причин — Machine, Method, Material, Man, Measurement, Mother Nature (Environment). Отрасль: услуги = 5P (People, Process, Place, Product, Promotion). Строить: голова = проблема, кости = категории причин, прутья = конкретные причины. Combine с 5 Why: для каждой ветви. | Не путать: cause diagram ≠ solution. После RCA → corrective action. |
| qualitymgmt.ops.calibration_program | Calibration — ANSI/NCSL Z540 | METHOD | Программа калибровки: все измерительные инструменты из контрольных планов → в календарный план калибровки. NIST traceable. Cal interval: based on usage, history, criticality. Out-of-tolerance: оценить влияние (продукция + уже выпущенная). ISO 17025: компетентность лабораторий (calibration + testing). | Recall: если оборудование было разлажено → все измерения от последней калибровки сомнительны. |
| qualitymgmt.ops.customer_complaint_8d | Customer Complaint — SCAR | METHOD | Жалоба клиента → Supplier Corrective Action Request (SCAR): 8D format. Containment: стоп-отгрузка, isolation affected parts. RCA within 5-7 дней. Corrective Action: specific, timely. Verification: evidence that CA was effective. Closure: клиент подтверждает удовлетворение. Рекуррентная жалоба: escalation. | Повторная жалоба по той же причине: свидетельство неэффективного RCA. |
