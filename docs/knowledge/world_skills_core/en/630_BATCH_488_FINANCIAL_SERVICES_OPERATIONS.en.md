| finance.ops.bank_teller_transactions | Bank Teller — Transaction Processing | PROCESS | Работа кассира в банке. Утро: приём наличных (cash drawer count, verify against system), dual control (два сотрудника открывают/закрывают хранилище). Транзакция: 1) идентификация клиента (ID, биометрия, knowledge-based authentication), 2) понимание запроса (слушать, перефразировать), 3) выполнение (deposit — cash-in, verify count на счётчике банкнот; проверка подлинности — UV, магнитные метки, водяной знак; withdrawal — count cash трижды: из drawer → на стойку клиенту → клиент считает при кассире), 4) получение подписи/подтверждения. Cash drawer: должен балансироваться в конце смены до копейки. Расхождение: пересчёт, камеры, audit. CTR (Currency Transaction Report): cash транзакция >$10000 через FinCEN (anti-money laundering). SAR (Suspicious Activity Report): подозрительная транзакция любого размера — структурирование (несколько депозитов чуть ниже $10000 для избежания CTR). Red flags: клиент нервничает, не может объяснить источник средств, структурирование. | Банкноты проверяются: UV light (встроенные волокна светятся), магнитная полоса на $20+ (1996+), цветопеременная краска ($10+ — цифра меняет цвет при наклоне), microprinting, watermarks. Поддельная купюра: задержать (неконфронтационно: «одну минуту, сверюсь с менеджером»), уведомить Secret Service (в США). |
| finance.ops.loan_underwriting | Loan Underwriting — 5 Cs of Credit | METHOD | Анализ кредитоспособности (5 Cs): 1) Character (кредитная история — FICO score 300-850, payment history 35%, amounts owed 30%, length 15%, new credit 10%, mix 10%. Subprime <620, near-prime 620-680, prime 680-740, super-prime >740), 2) Capacity (способность платить — DTI (debt-to-income ratio): front-end (housing/income <28%), back-end (all debt/income <36%, до 43% для qualified mortgage), residual income для VA loans), 3) Capital (собственный взнос: conventional 20% (или PMI), FHA 3.5%, VA 0%, USDA 0% — чем меньше взнос, тем выше риск для банка), 4) Collateral (LTV — loan-to-value ratio <80% для prime, appraisal подтверждает стоимость залога), 5) Conditions (цель кредита, сумма, rate — фиксированная/плавающая, срок, economic conditions). Для бизнеса дополнительно: cash flow analysis (достаточен ли операционный денежный поток для обслуживания долга? DSCR — debt service coverage ratio >1.25), бизнес-план, industry risk. | Автоматическое underwriting (DU — Desktop Underwriter для Fannie Mae, LP — Loan Prospector для Freddie Mac): алгоритм принимает решение за минуты для простых случаев. Manual underwriting для сложных (self-employed с переменным доходом — tax returns 2 года, P&L, банковские выписки). Disparate impact: алгоритмы не должны дискриминировать protected classes (ECOA — Equal Credit Opportunity Act). |
| finance.ops.insurance_claims_processing | Insurance Claims — Property & Casualty | PROCESS | Обработка страхового иска (claim). FNOL (First Notice of Loss): клиент сообщает о повреждении → claim number assigned → adjuster assigned. Investigation: 1) coverage check (действовал ли полис на момент события? covered peril? исключения?), 2) liability determination (кто виноват? comparative/contributory negligence), 3) damage assessment (adjuster осматривает повреждения: авто — collision vs comprehensive; имущество — roof, water, fire), оценка (Xactimate для строительства, Mitchell/CCC для авто), 4) Reserve setting (оценка ultimate cost — сколько страховая заплатит в итоге). Settlement: adjuster предлагает сумму на основе оценки → переговоры с клиентом/адвокатом → acceptance or litigation. Payment: repair directly to body shop/contractor (direct repair program) or reimbursement клиенту. Subrogation: если клиент не виноват, страховая платит клиенту и сама предъявляет иск виновнику/его страховой для возврата. | Claims — момент истины для страховой (клиент платил премии годами, теперь страховая должна быть на его стороне). Bad faith: задержка без причины, необоснованный отказ, низкое предложение — lawsuit against insurer (punitive damages возможны). |
| finance.ops.branch_cash_management | Branch — Cash Management & Vault Operations | METHOD | Управление наличными в отделении банка. Инкассация: CIT (cash-in-transit) компания (Brinks, Loomis) доставляет/забирает наличные по расписанию и по вызову. Vault (хранилище): двойной контроль (dual control — всегда два сотрудника, один открывает один наблюдает). Cash ordering: прогноз спроса (пятница/понедельник перед выходными — больше наличных, праздники — больше, конец месяца — зарплаты), заказ в Fed/Центробанк за 1-5 дней. ATM replenishment: загрузка кассет в банкомат (4 кассеты по 2000+ банкнот), балансировка (предыдущий остаток + загрузка − выдача = текущий остаток), journal printer (запись всех транзакций). Excess cash: сдаётся в Fed через CIT. Страхование: cash in vault застрахован до определённого лимита (превышение не страхуется → отправлять в Fed чаще). Нумерация банкнот: для tracking в случае robbery (bait money — записанные серийные номера нескольких купюр в каждой кассете). | Dual control — основной принцип безопасности (ни один человек не имеет sole access к наличности/хранилищу). Robbery procedure: comply (отдать деньги, не геройствовать), activate alarm (silent, ногой/кнопкой), observe (запомнить внешность/голос/vehicle/направление), secure (закрыть отделение, не трогать улики), notify (supervisor + police). |
| finance.ops.anti_fraud_transaction | Anti-Fraud — Transaction Monitoring | METHOD | Обнаружение мошеннических транзакций. Rule-based: transaction amount >X, location отличается от home (невозможно долететь за 2 часа — Чикаго → Лондон), frequency (3+ online покупок за 5 минут), merchant category (покупка электроники если ранее никогда). ML-based: нейронная сеть обучена на исторических данных (fraud patterns), anomaly detection, score 0-1000 (1000 = certain fraud). Response: 1) Decline (отклонить транзакцию — высокий риск), 2) Challenge (SMS/email/push: «транзакция на $X в Y. Это вы? Подтвердите»), 3) Allow (низкий риск). False positive management: слишком агрессивный fraud detection → declined legitimate transactions → клиент раздражён, уходит. Ratio: false positive <5:1 (5 legitimate declined на 1 fraud caught — industry benchmark). Для карт: 3DS (3-D Secure — Verified by Visa/Mastercard SecureCode): дополнительный шаг аутентификации через одноразовый код (PSD2 SCA — Strong Customer Authentication в EU). Liability shift: если выпущена 3DS, liability за fraud переходит от merchant к issuer. | Card testing: мошенники проверяют украденные номера карт на микро-транзакциях ($0.01) → если проходят → крупная покупка. Velocity checks: более 3 declined транзакций с одного IP за 5 мин → блок. |
| finance.ops.retail_banking_sales | Retail Banking — Needs-Based Selling | METHOD | Продажи банковских продуктов на основе потребностей (не навязывание). Процесс: 1) Greeting & rapport (small talk), 2) Discovery (открытые вопросы: «какие у вас финансовые цели на ближайший год?»), 3) Needs analysis («вы упомянули что копите на дом — расскажите подробнее»), 4) Solution presentation (подобрать продукт под потребность: high-yield savings → CD для краткосрочных целей, кредитная карта с кэшбеком → travel rewards если клиент много путешествует, HELOC для ремонта, investment account для долгосрочного роста), 5) Handle objections («я не хочу платить annual fee» → «с вашим расходом $2000/мес, кэшбек $240/год перекрывает $95 fee»), 6) Close, 7) Follow-up (звонок через 2 недели — всё ли устраивает?). Referrals: «возможно, ваш супруг/коллега тоже заинтересуется?». Compliance: обязательные disclosures (APR, fees, terms), cooling-off period, suitability (не предлагать risky investments консервативному клиенту). | Mystery shopping: банки проверяют что сотрудники не mis-sell и дают полную информацию. Wells Fargo scandal (2016): сотрудники открывали 3.5M фальшивых счетов для выполнения планов продаж → $3B штраф. Урок: sales targets должны быть разумны чтобы не провоцировать unethical behaviour. |
