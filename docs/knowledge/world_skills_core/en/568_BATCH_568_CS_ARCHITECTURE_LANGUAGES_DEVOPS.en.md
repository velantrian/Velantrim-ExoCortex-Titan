| cs.architecture.cpu_pipeline | CPU Pipeline — IF/ID/EX/MEM/WB | INVARIANT | 5 стадий RISC: выборка инструкции, декодирование, выполнение, обращение к памяти, запись результата. Pipeline hazards: структурные (конфликт ресурсов), данных (RAW, WAR, WAW), управления (ветвления). Forwarding/bypassing решают data hazards. | Глубина пайплайна: Pentium 4 — 31 стадия (NetBurst, высокие частоты но низкий IPC), современные: ARM/Apple M1 — широкий, но короткий (~8 стадий). Branch mispredict penalty растёт с глубиной. |
| cs.architecture.cache | Cache Hierarchy — L1/L2/L3 | INVARIANT | L1 (разделённый I/D, ~3 такта, 32-64 КБ). L2 (унифицированный, ~10 тактов, 256-512 КБ). L3 (общий для ядер, ~30-50 тактов, МБ). Ассоциативность: direct-mapped (1-way), N-way set associative, fully associative. Замещение: LRU, pseudo-LRU, RRIP. | 90-95% попаданий L1, 50-60% из оставшихся — L2, и т.д. Cache line 64 байта (пространственная локальность). False sharing: два ядра пишут в разные переменные одной кэш-линии → неоправданная инвалидация. |
| cs.architecture.branch_prediction | Branch Prediction | METHOD | Статический (всегда не переходим, всегда назад переход для циклов). Динамический: двухбитный счётчик (2-bit saturating counter), двухуровневый (Bimodal), Gshare (глобальная история XOR с PC), Tournament (гибрид: TAGE — TAgged GEometric, победитель предсказателей). Современная точность >97%. | Самые современные предсказатели: Perceptron (нейрон), TAGE-SC-L (Andre Seznec). Miss-predict → сброс части пайплайна → 15-20 тактов потери. |
| cs.architecture.out_of_order | Out-of-Order Execution | PROCESS | Инструкции выполняются по готовности операндов, а не в порядке программы (независимые — параллельно). Reservation stations (Tomasulo algorithm), Reorder Buffer (ROB — восстановление порядка для исключений и точных прерываний), Register renaming (устранение ложных зависимостей WAR, WAW). | Физических регистров больше, чем архитектурных (архитектурно 32, физически 160-200). Micro-ops (μops) вместо x86 CISC инструкций (декодируются в RISC-like). |
| cs.architecture.isa | ISA — RISC vs CISC | VARIANT | RISC (ARM, RISC-V): load-store архитектура, фиксированная длина инструкции (32 бита), простое декодирование. CISC (x86-64): сложные инструкции, переменная длина, микроархитектура — RISC внутри. | RISC-V — открытый стандарт (free ISA, расширяемый). Apple M1: ARM RISC + wide decode (8 инструкций/цикл) → революционная производительность/Вт. |
| cs.architecture.simd | SIMD & Vectorization | METHOD | Одна инструкция → операция над несколькими данными. MMX (64 бит) → SSE (128, 4×float) → AVX (256) → AVX-512 (512 бит, старшие модели Xeon). ARM: NEON 128-бит. | Применение: обработка изображений, матричные умножения, ML инференс (квантизованные модели), DSP. Автовекторизация компилятора или ручные интринсики. |
| cs.architecture.gpu_arch | GPU Architecture — SIMT | METHOD | Thousands of cores, grouped in warps (NVIDIA, 32 threads) / wavefronts (AMD, 64). SIMT: same instruction, different data across threads. Иерархия памяти: global (VRAM, медленная, большая), shared (on-chip, быстрая, для блока), локальная (регистры — приватные). | GPU-ядра проще CPU: нет сложного branch prediction, out-of-order, маленький кэш (зато массивный параллелизм). Tensor Cores (NVIDIA, 2017): матричное умножение 4×4 за такт. |
| cs.languages.type_systems_comparison | Type Systems — Static vs Dynamic | VARIANT | Статическая (C, Rust, Haskell): типы проверяются на этапе компиляции. Динамическая (Python, JS, Ruby): во время выполнения. Сильная vs слабая типизация: насколько строго соблюдаются типы. Манифестная vs выводимая (ML: компилятор сам выводит типы). | Gradual typing (TypeScript, Python type hints + mypy) — мост между мирами. Structural typing (TypeScript: совместимость по структуре полей) vs nominal (имя типа). |
| cs.languages.memory_management | Memory Management — Manual vs GC | METHOD | Ручное (C malloc/free, C++ new/delete + RAII/умные указатели). Подсчёт ссылок (Python, Swift, Objective-C ARC). Трассирующий GC (Java, Go, C#): Mark-and-sweep (пометка достижимых → сборка мёртвых), Generational (молодые объекты умирают раньше), Copying (перемещение живых, дефрагментация). | Stop-the-world паузы — проблема для real-time (Go: latency < 1ms, Java ZGC/Shenandoah: субмиллисекундная). Arena/Region-based (Rust — время жизни, Zig). |
| cs.languages.functional_programming | Functional Programming | INVARIANT | Чистые функции (без побочных эффектов), иммутабельность, функции высшего порядка, алгебраические типы данных, pattern matching, монады (в Haskell для I/O). λ-исчисление — теоретическая основа. | Преимущества: легкость рассуждения, параллелизм (нет гонок данных), тестирование. Недостатки: кривая обучения, производительность (иногда). |
| cs.languages.rust_ownership | Rust — Ownership System | METHOD | Каждое значение имеет ровно одного владельца. Перемещение (move) передаёт владение. Заимствование: &T (иммутабельное, множественное) или &mut T (мутабельное, эксклюзивное — не оба одновременно). Время жизни (lifetimes) — проверка на этапе компиляции. | Безопасность памяти без GC, без data races. Применимо в системном программировании, WebAssembly, embedded. Управление ресурсами через Drop (RAII). |
| cs.devops.ci_cd | CI/CD Pipeline | METHOD | Непрерывная интеграция: каждый push → build + test + lint (автоматически, минуты). Непрерывная доставка (Continuous Delivery): каждый merge → staging (ручное одобрение на prod). Непрерывное развёртывание (Continuous Deployment): автоматически в prod после тестов. Jenkins, GitHub Actions, GitLab CI. | Trunk-based development: частые мелкие коммиты в main (не долгоживущие feature branches). Feature flags для постепенного rollout. Canary deployments (малый процент → мониторинг → rollout). |
| cs.devops.containerization | Containers & Docker | METHOD | Образ: слои файловой системы (union FS), свой PID/net/mount namespace (изоляция через cgroups + namespaces), разделяемое ядро хоста. Dockerfile: FROM, RUN, COPY, CMD. Registry: Docker Hub, ECR, GCR. | Микросервисы: каждый в контейнере, оркестрация Kubernetes. Лёгковесность vs VM (нет гостевой ОС). Недостаток: изоляция слабее, чем у VM (общее ядро). |
| cs.devops.kubernetes | Kubernetes Concepts | METHOD | Pod (минимальная единица — 1+ контейнеров, общие сеть/volumes), Service (стабильный IP/DNS для набора Pods), Deployment (желаемое состояние: replicas, rolling update), ConfigMap/Secrets, Ingress (внешний HTTP/S доступ), Namespaces, Persistent Volume Claims. | Self-healing: упавший Pod перезапускается. Horizontal Pod Autoscaler (HPA) — по CPU/метрикам. Service mesh (Istio/Linkerd) — наблюдаемость, трафик-менеджмент. |
