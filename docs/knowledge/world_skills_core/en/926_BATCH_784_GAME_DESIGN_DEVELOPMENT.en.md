# BATCH 784: Game Design — Mechanics & Development

**KnowledgeUnits:** 50
**Namespace:** `gamedesign.ops.*`
**Scope:** game_mechanics, level_design, game_balance, progression_systems, narrative_design, UI_UX_games, monetization, playtesting, player_psychology

| ID | KnowledgeUnit | Тип | Суть | Практический смысл |
|---|---|---|---|---|
| gamedesign.ops.core_loop | Core Loop — Design | METHOD | Основной игровой цикл (Core Loop): центральная повторяющаяся игровая деятельность. Состав: Encounter (встретить вызов) → Overcome (преодолеть) → Reward (получить награду) → Repeat. Примеры: Candy Crush = match tiles → clear level → new level. Fortnite = land → loot → fight → survive. Engagement: цикл должен быть достаточно коротким и удовлетворяющим. | Retention: если core loop не fun, никакой meta-design не исправит. |
| gamedesign.ops.game_feel_juice | Game Feel — Feedback & Polish | METHOD | Игровое ощущение (Game Feel): ответная реакция игры на действия игрока. Screen shake, particle effects, sound effects, animations. «Juice»: полирующие эффекты, делающие обычные действия удовлетворяющими. Squash and stretch: визуальные деформации. Haptic feedback: мобильные/консоль контроллеры. | Сравнение Juice: без juice = механически правильно но «мёртво». С juice = то же самое «живёт». |
| gamedesign.ops.level_design_principles | Level Design — White Boxing | METHOD | Проектирование уровней: Blockout/Greybox/Whitebox: быстрые грубые геометрические прототипы без арта. Player flow: направление игрока через вызовы. Cadence: чередование интенсивности (bait-switch patterns). Safe zones vs danger zones. Landmarks: помогают навигации. Teach → Test → Twist: прогрессия обучения. | Whitebox тестирование: 80% проблем обнаруживаются ещё без арта. |
| gamedesign.ops.mda_framework | MDA Framework — Design | METHOD | MDA Framework (Hunicke, LeBlanc, Zubek): Mechanics (правила системы) → Dynamics (поведение при взаимодействии) → Aesthetics (эмоциональные отклики). Как дизайнер: начинает с Mechanics. Как игрок: видит Aesthetics первым. 8 эстетик: Sensation, Fantasy, Narrative, Challenge, Fellowship, Discovery, Expression, Submission. | MDA: инструмент для анализа и критики игровых дизайнов. |
| gamedesign.ops.balance_theory | Game Balance — Designer Types | METHOD | Баланс в играх: Symmetric vs Asymmetric balance. Combinatorial explosion: слишком много опций → неуправляемое тестирование. Dominant strategy: одна стратегия лучше всех → снижает разнообразие. Transitive vs Intransitive balance: A>B>C vs Rock-Paper-Scissors. Internal economy: вход/выход ресурсов. | Интранзитивный баланс (RPS): гарантированно нет dominant strategy. |
| gamedesign.ops.narrative_player_agency | Narrative Design — Agency | METHOD | Нарративный дизайн: Player agency = ощущение влияния на историю. Четыре I's: Interactive, Immersive, Iterative, Impactful. Environmental storytelling: история без текста (Deus Ex, Dark Souls). Dialogue trees: линейные vs ветвящиеся vs simulators. Lore depth: необязательная глубина (лорные книги). | «Show don't tell»: показать через gameplay, а не cutscene. |
| gamedesign.ops.progression_systems | Progression — Skill vs Gear | METHOD | Системы прогресса: Skill-based: улучшается сам игрок (Fighting games). Gear-based: персонаж становится мощнее (RPG). Hybrid: Souls series (навык + статы + оборудование). Power creep: неконтролируемый рост силы. Replayability: разные пути/билды. Mastery curve: Novice → Advanced → Expert. | GaaS (Games as a Service): seasons + battle pass = непрерывная прогрессия. |
| gamedesign.ops.difficulty_scaling | Difficulty Design — Dynamic Adjustment | METHOD | Настройка сложности: Static: фиксированные уровни (Easy/Normal/Hard). Dynamic Difficulty Adjustment (DDA): адаптация к производительности игрока. Rubber-banding: более слабые получают небольшой буст. Flow theory (Csikszentmihalyi): задача немного сложнее навыка = потоковое состояние. First-time user experience (FTUE): особенно мягкое начало. | RE4 DDA: монстры подстраиваются к успехам игрока (незаметно). |
| gamedesign.ops.monetization_f2p | Monetization — F2P Ethics | METHOD | Монетизация F2P игр: Cosmetic-only: только внешние предметы без влияния на баланс. Pay-to-Win: преимущество в геймплее за деньги (контроверсно). Gacha/Loot boxes: вероятностные reward. Season pass vs Battle pass. WhaleTrack: 5-7% игроков = 50%+ выручки. FTC и ESRB: регулирование loot boxes. | FOMO (Fear of Missing Out): временные предложения → эксплуататорный дизайн. |
| gamedesign.ops.playtest_methods | Playtesting — Iterative | METHOD | Плейтестирование: Think Aloud Protocol: игрок говорит вслух. Observational: молча наблюдать. Heuristic evaluation: применить список эвристик. A/B testing: две версии. Analytics: data-driven decisions. Session replay. Types of testers: friends/family (too lenient), target audience, unfamiliar testers. | «Watching someone struggle is painful but necessary» — не объяснять, наблюдать. |
| gamedesign.ops.fps_fps_design | FPS Design — Feel & Movement | METHOD | Шутеры от первого лица (FPS): Weapon feel: weight + recoil + sound. Movement: WASD + mouse look (настройка sensitivity). FOV (Field of View): 90-110° горизонтальный. Headbob: имитация ходьбы (часто отключаемый). Netcode: lag compensation, client prediction. Hitbox accuracy. | Mouse acceleration: большинство pro-players отключают (1-to-1 movement). |
| gamedesign.ops.rts_design | RTS Design — Economy Loops | METHOD | Стратегии в реальном времени (RTS): Worker → Resource → Production → Combat loop. Macro (экономика) vs Micro (юниты). Worker harassment: экономическое давление. Tech tree: временная прогрессия. Поздняя игра (late game): массированные битвы. Supply/population cap: снижение snowball. | StarCraft 2: APM (actions per minute) = мера навыка. |
| gamedesign.ops.roguelite_design | Roguelite — Design Principles | METHOD | Roguelite: процедурная генерация + permadeath + прогрессия между запусками. Метапрогрессия: постоянные улучшения. Run variety: разные билды каждый раз. Синергии предметов: взаимодействие усиляет (Binding of Isaac). Risk/reward: опасные комнаты = лучшие награды. | Roguelike vs Roguelite: roguelike = строгий permadeath. roguelite = прогрессия между runs. |
| gamedesign.ops.open_world_design | Open World — Design Challenges | METHOD | Открытый мир: Content density: предотвращение «пустых» зон. Point of interest density: примерно каждые 200-400 метров. Navigation: map, markers, organic cues. Dynamic world: события без участия игрока. LOD (Level of Detail): качество → расстоянию. Streaming: непрерывная загрузка. | «Walking simulator» problem: путешествие без контента = boring. |
| gamedesign.ops.couch_coop | Couch Co-op — Split Screen | METHOD | Локальный кооператив: split-screen: вертикальный или горизонтальный. Кусок экрана = 50% каждому. Camera management: shared vs individual. Лидер и лагмейт (follower): проблема «getting left behind». Asymmetric roles: разные роли усиливают сотрудничество. Performance hit: два рендера одновременно. | Lokale multiplayer revival: Among Us, Overcooked, Jackbox Games. |
| gamedesign.ops.sound_design_games | Sound Design — Diegetic vs Non-Diegetic | METHOD | Звуковой дизайн игр: Diegetic sound: исходит из игрового мира (шаги, выстрелы, диалоги). Non-diegetic: существует вне мира (музыка, UI звуки). Meta-diegetic: пограничное. Adaptive music: изменяется по состоянию игры (combat vs exploration). FMOD, Wwise: middleware для adaptive audio. | Звук передаёт пространственную информацию: 3D звук в FPS = critical gameplay element. |
| gamedesign.ops.tutorial_design | Tutorial — Onboarding | METHOD | Туториал (обучение): Not a wall of text. «Nintendo method»: обучение через контекст. Delayed tutorialization: показывать только когда нужно. Safe space to fail: без последствий во время обучения. «Hidden tutorial»: обучение через контент (Portal). Hard gate: нельзя пройти без усвоения. | Онбординг: 60% игроков бросают в первые 5 минут — почему? |
| gamedesign.ops.player_archetype_bartle | Player Types — Bartle's Taxonomy | METHOD | Таксономия игроков Бартла: Killers: соревнование с другими игроками. Achievers: выполнение целей, очки, трофеи. Socializers: взаимодействие с другими. Explorers: исследование мира и системы. Nick Yee (MMORPG): Achievement, Social, Immersion. Design game elements for multiple types. | Многие успешные игры охватывают все 4 типа (World of Warcraft). |
| gamedesign.ops.emergent_gameplay | Emergent Gameplay — Player-Driven | METHOD | Эмерджентный геймплей: непредвиденные игроками и разработчиками способы взаимодействия с системой. Открытые системы: взаимодействующие системы → незапланированное. Zelda: Breath of the Wild = физика + химия → решения без туториала. Minecraft = блоки + физика → бесконечные конструкции. | «Best games are not what you design but what emerges from systems». |
