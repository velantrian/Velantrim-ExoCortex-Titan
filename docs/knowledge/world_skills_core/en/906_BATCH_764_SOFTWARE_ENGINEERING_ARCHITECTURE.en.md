Принципы: Single Responsibility, автономность, own data (no shared database), API first. Communication: sync (REST/gRPC) vs async (event/queue). | softeng.ops.rest_api_design | REST API — Design Principles | METHOD | RESTful API: Resources: URI = noun (/users/{id}). | softeng.ops.cap_theorem | CAP Theorem — Distributed Systems | METHOD | CAP теорема (Brewer): в распределённой системе при сетевом разделении (Network Partition) нельзя одновременно иметь Consistency и Availability. CP: согласованность (MongoDB, HBase). AP: доступность (CouchDB, Cassandra). CA: без партиций (одиночный сервер). PACELC: расширение CAP (добавляет latency vs consistency trade-off). | Real-world: всегда есть сетевые сбои → выбор CP vs AP. |
| softeng.ops.database_normalization | Database — Normalization Forms | METHOD | Нормализация: 1NF: атомарные значения (нет множественных значений в ячейке). 2NF: нет частичных зависимостей (все неключевые атрибуты зависят от ВСЕГО первичного ключа). 3NF: нет транзитивных зависимостей. BCNF: каждый детерминант = суперключ. 4NF: нет многозначных зависимостей. | Денормализация: для read-performance (аналитические запросы). |
| softeng.ops.testing_pyramid | Testing Pyramid — Strategies | METHOD | Пирамида тестирования: Unit tests (основание): быстрые, изолированные. Integration tests (средний слой): несколько компонентов. E2E tests (вершина): всё приложение. AAA pattern (Arrange-Act-Assert). TDD (Test-Driven Development): сначала тест. Mocking: фиктивные зависимости. Coverage: 80%+ unit. | Anti-pattern: Ice-cream cone (много E2E, мало unit). |
| softeng.ops.event_driven_saga | Event-Driven — Saga Pattern | METHOD | Saga Pattern: для distributed transactions без two-phase commit. Event Sourcing: хранить события как источник истины. CQRS (Command Query Responsibility Segregation): разделить read и write модели. | Distributed transactions: нет единственного правильного решения (Saga vs 2PC trade-offs). |
