| telecom.ops.osi_model_layers | OSI Model — 7 Layers | METHOD | Модель OSI: L1 Physical (бит, кабель, сигнал). L2 Data Link (MAC, Ethernet, VLAN). L3 Network (IP, маршрутизация). L4 Transport (TCP/UDP, порты). L5 Session (установление/поддержание сессий). L6 Presentation (шифрование, форматы). L7 Application (HTTP, DNS, SMTP). Мнемоника: «Please Do Not Throw Sausage Pizza Away». | TCP/IP не OSI: Internet model (Link/Internet/Transport/Application). |
| telecom.ops.bgp_routing | BGP — Border Gateway Protocol | METHOD | BGP (Border Gateway Protocol): межавтономный routing (EGP). Атрибуты пути: AS-PATH, LOCAL-PREF, MED, NEXT-HOP, ORIGIN. iBGP vs eBGP: iBGP (внутри AS, loop prevention = not re-advertise), eBGP (между AS). Route selection: longest prefix → highest LOCAL_PREF → shortest AS_PATH → lowest MED → eBGP over iBGP → lowest router ID. | BGP hijacking: объявить чужой prefix → трафик перенаправляется (случается регулярно). |
| telecom.ops.mpls_label_switching | MPLS — Label-Based Forwarding | METHOD | MPLS (Multiprotocol Label Switching): метки (labels) вместо IP routing. Ingress LER: добавить MPLS label. Core LSR: forwarding по label (без IP lookup). Egress LER: убрать label. Label stack: несколько меток. Traffic Engineering (MPLS-TE): explicit routing. VPN (L3VPN, L2VPN): MPLS-based services. | MPLS faster: не глубокий IP-lookup в ядре (label = fixed length). |
| telecom.ops.qos_dscp_marking | QoS — DSCP Marking | METHOD | Quality of Service (QoS): DSCP (Differentiated Services Code Point): 6 бит в IP header. EF (Expedited Forwarding, DSCP 46): VoIP (lowest latency). AF (Assured Forwarding) 4 classes: AF41 (video). CS (Class Selector) 1-7. BE (Best Effort = default = CS0). Queuing: Priority Queue (PQ), CBWFQ, WFQ. Policing vs Shaping: policing = drop, shaping = delay. | VoIP: нужен EF + jitter buffer <150 мс для речи. |
| telecom.ops.fiber_optic_types | Optical Fiber — Singlemode vs Multimode | METHOD | Одномодовый (SMF): диаметр ядра 8-10 мкм. Один световой путь. Расстояние: 100+ км без усиления (DWDM). Многомодовый (MMF): 50/62.5 мкм. Несколько мод → modal dispersion. Расстояние: 550 м (OM3), 2000 м (OM4/OM5) при 10G. Коэффициент преломления: ступенчатый vs градиентный. OTDR: рефлектометрия для обнаружения точек потерь. | SMF для межстроечных соединений. MMF для локальных коротких пробегов. |
| telecom.ops.5g_nr_bands | 5G NR — Frequency Bands | METHOD | 5G NR (New Radio): FR1 (Sub-6 GHz): 600 MHz - 6 GHz (широкий охват). FR2 (mmWave): 24-100 GHz (высокая ёмкость, короткий радиус). Subcarrier spacing: 15 kHz (FR1), 30 kHz, 60 kHz (FR1), 120 kHz (FR2). Bandwidth: 5-100 MHz (FR1), 50-400 MHz (FR2). NR Architecture: gNB (базовая станция), CU/DU split. NSA (non-standalone) vs SA (standalone). | mmWave: макс. скорость (multi-Gbps) но плохое распространение (здания, дождь). |
| telecom.ops.voip_codec_sip | VoIP — SIP Signaling | METHOD | VoIP: SIP (Session Initiation Protocol): установление/завершение сессий. RTP (Real-time Transport Protocol): медиа поток. INVITE → 100 Trying → 180 Ringing → 200 OK → ACK. BYE для завершения. Codec: G.711 (64 кбит/с, PSTN quality), G.729 (8 кбит/с, хорошее качество, compressed), Opus (адаптивный). MOS (Mean Opinion Score): 1-5 (>4 = хорошо). | Jitter buffer: выравнивает задержки пакетов. Too large → delay. Too small → gap. |
| telecom.ops.sdwan_overlay | SD-WAN — Overlay Architecture | METHOD | SD-WAN (Software-Defined WAN): управление несколькими WAN (MPLS + Internet + 4G). Controller: централизованная политика. Overlay: зашифрованные туннели IPsec/DTLS. Underlay: физический транспорт. Application-aware routing: приложения → оптимальный путь. Zero-touch provisioning (ZTP): автоматическая конфигурация. Vendors: Cisco Viptela, VMware VeloCloud, Aruba. | SD-WAN vs MPLS: Internet + IPSEC = 80% of cost, similar performance for most applications. |
| telecom.ops.ipv6_addressing | IPv6 — Address Structure | METHOD | IPv6: 128 бит (32 шестнадцатеричных). Типы: Unicast (Global, Link-local, Loopback::1). Multicast (FF::/8). Anycast: одинаковый адрес у нескольких нод. SLAAC: автоконфигурация из Router Advertisement. DHCPv6: управляемое распределение. EUI-64: MAC → IID. Dual-stack: IPv4 и IPv6 параллельно. Tunneling: 6to4, 6in4 (6over4). | Istощение IPv4: IPv6 развертывание >50% трафика Google (2023). |
| telecom.ops.tcp_congestion_control | TCP — Congestion Control | METHOD | TCP управление перегрузкой: Slow Start: cwnd = 1 MSS → экспоненциальный рост до ssthresh. Congestion Avoidance: linейный рост. Fast Retransmit: 3 dupACK → retransmit без ожидания timeout. Fast Recovery. BBR (Bottleneck Bandwidth and RTT): Google — основана на измерении bandwidth + RTT (vs потерях). CUBIC: default Linux (f(RTT) curve). | BBR vs CUBIC: BBR лучше в высоком BDP (bandwidth-delay product) environments. |
| telecom.ops.dns_resolution | DNS — Resolution Process | METHOD | DNS разрешение: recursive resolver запрашивает. Root NS → TLD NS (.com) → Authoritative NS → IP. Caching: каждый уровень кэширует по TTL. DNSSEC: цифровые подписи DNS записей. DoH (DNS over HTTPS): шифрованный DNS. Types: A (IPv4), AAAA (IPv6), MX (mail), CNAME (alias), TXT (verification), PTR (reverse). Zone transfer: AXFR. | DNS amplification attack: малый запрос → большой ответ (DDoS amplification). |
| telecom.ops.network_monitoring_snmp | Network Management — SNMP | METHOD | SNMP (Simple Network Management Protocol): v2c (community string, простой), v3 (authentication + encryption). MIB (Management Information Base): дерево OID. Polling vs traps. SNMP GET, GETNEXT, GETBULK, SET, TRAP. Графики: MRTG, Cacti, Grafana + SNMP. NetFlow/IPFIX: анализ трафика (source, destination, bytes). | SNMP v2c: community string в plain text → перехват. v3 обязателен для production. |
| telecom.ops.wireless_spectrum | Wireless — Channel Planning | METHOD | Планирование каналов: Wi-Fi 2.4 GHz: каналы 1, 6, 11 (не перекрываются). Wi-Fi 5 GHz: 23 20MHz канала (нет overlay). Wi-Fi 6E (6 GHz): 59 20MHz канала. Cellular reuse: frequency reuse factor. Interference: co-channel (adjacent APs same channel) vs adjacent-channel. AP placement: каждые 30-50 м для office. | 5 GHz: менее перегружен чем 2.4 GHz но меньший радиус. |
| telecom.ops.optical_amplifier_edfa | Optical Amplification — EDFA | METHOD | Эрбиевый волоконный усилитель (EDFA): Er³⁺ ионы в фторидном волокне → население 1.55 мкм диапазона. Pump: 980 нм или 1480 нм лазер. Усиление: 25-40 dB без восстановления. DWDM: Dense WDM (100 GHz или 50 GHz spacing). ASE (Amplified Spontaneous Emission): шум усилителя. Noise Figure: 3-5 dB. | EDFA + WDM = трансокеанские кабели (тысячи км без регенерации). |
| telecom.ops.network_slicing_5g | 5G Network Slicing | METHOD | Слайсинг 5G сети: создание логически изолированных виртуальных сетей поверх общей физической инфраструктуры. eMBB (enhanced Mobile Broadband): высокая скорость. URLLC (Ultra-Reliable Low Latency): <1 мс latency. mMTC (massive Machine-Type Comm): IoT. Технологии: NFV (Virtual Network Functions) + SDN. 3GPP slices: идентификатор S-NSSAI. | Industrial 5G: URLLC slice для роботов, AGVs с детерминированной задержкой. |
| telecom.ops.fiber_latency_calculate | Latency — Fiber Propagation | METHOD | Задержка в оптическом волокне: скорость света в вакууме c = 3×10⁸ м/сек. В SMF: n ≈ 1.468 → v = c/n ≈ 2.04×10⁸ м/сек. 1 мс latency = 204 км. NYC-London (5500 км) = ~27 мс one-way. Обратная связь (RTT): × 2. Propagation + switching + queuing = total delay. | Low-latency trading: физическое расстояние критично (HFT colocation). |
| telecom.ops.nat_pat_traversal | NAT — Port Address Translation | METHOD | Network Address Translation (NAT): частные IP → публичный IP. PAT (Port Address Translation) / NAT overload: один публичный IP + уникальные порты для каждого потока. Connection tracking: state table. NAT traversal (VoIP, P2P): STUN, TURN, ICE. Static NAT: фиксированное соответствие 1:1. 1:N PAT: масштабирование. | CGN (Carrier-Grade NAT): ISP NAT за ISP → double NAT (проблема для приложений). |
| telecom.ops.error_detection_correction | Error Control — FEC & ARQ | METHOD | Коррекция ошибок: FEC (Forward Error Correction): избыточность в потоке данных, получатель исправляет без retransmission. Reed-Solomon: CD, QAM. Turbo codes, LDPC (5G NR). ARQ (Automatic Repeat reQuest): запрос повторения при ошибке. Stop-and-Wait vs Go-Back-N vs Selective Repeat. HARQ: гибрид FEC + ARQ (4G/5G). | FEC vs ARQ: FEC = задержка не увеличивается, ARQ = полная коррекция (нужно RTT). |
| telecom.ops.cloud_radio_access | Cloud RAN — Architecture | METHOD | Облачная RAN (C-RAN/Open RAN): centralized baseband (BBU) обрабатывает сигналы от множества RRH (Remote Radio Heads). Fronthaul: RRH-BBU (CPRI/eCPRI, очень низкая задержка). Midhaul: DU-CU. Backhaul: CU-Core. O-RAN Alliance: открытые интерфейсы. Disaggregation: vendor mix. AI/ML: для оптимизации. | O-RAN: конкуренция + экономия vs традиционный vendor lock-in. |
