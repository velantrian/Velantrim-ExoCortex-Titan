| blockchain.ops.pow_consensus | Proof of Work — Mining Mechanics | METHOD | Доказательство работы (PoW): майнер подбирает nonce такой, что SHA-256(block_header) < target. Difficulty adjustment: каждые 2016 блоков (Bitcoin) → target изменяется чтобы среднее время блока = 10 мин. Hash rate: TH/s (TeraHash). 51% attack: контроль >50% hash rate → двойное расходование. ASIC: Application-Specific Integrated Circuit (только для SHA-256, неэффективен для других). | Energy consumption Bitcoin: ~150 TWh/год (2024) ≈ как Польша. |
| blockchain.ops.pos_validator | Proof of Stake — Validator | METHOD | Доказательство доли (PoS): валидаторы «ставят» (stake) криптовалюту как залог. Выбор пропонента блока: взвешенный по stake. Slashing: наказание за двойное голосование / off-line. Ethereum validator: минимум 32 ETH stake. Epoch/slot: 12-сек слот, 32 слота = 1 эпоха (6.4 мин). Finality: после 2 эпох (checkpoint). | Staking yield: 3-5% APR (Ethereum). Нет фиксированного (market-based). |
| blockchain.ops.hd_wallet_derivation | HD Wallet — BIP32/39/44 | METHOD | Hierarchical Deterministic Wallet (BIP32): одна seed-фраза → дерево ключей. BIP39: mnemonic (12-24 слова → seed). BIP44: derivation path m/44'/coin_type'/account'/change/address_index. Пример BTC: m/44'/0'/0'/0/0. Master private key → child private key → public key → address. Hardware wallet (Ledger, Trezor): хранит seed в защищённой среде. | Seed phrase = доступ ко всем адресам. Никогда не онлайн, не на фото. |
| blockchain.ops.evm_smart_contract | EVM — Smart Contract Execution | METHOD | Ethereum Virtual Machine (EVM): стековая машина. Opcode: низкоуровневые инструкции. Solidity → bytecode → EVM execution. Gas: стоимость каждого opcode (SSTORE = 20 000 gas). Gas limit: max gas для транзакции. Base fee + priority fee (EIP-1559). Reentrancy attack: внешний вызов до обновления состояния → рекурсивное изъятие (DAO hack 2016). | Checks-Effects-Interactions: паттерн для предотвращения reentrancy. |
| blockchain.ops.defi_amm | DeFi — AMM & Liquidity Pools | METHOD | Automated Market Maker (AMM): x × y = k (Uniswap v2). x и y — резервы токенов. Swap: изменяет x и y сохраняя k. Price impact: чем больше swap относительно pool — тем выше. Impermanent loss (IL): LP теряет при divergence цен vs HODL. Concentrated liquidity (Uniswap v3): LP выбирает ценовой диапазон. Fees: 0.05% / 0.3% / 1%. | AMM vs order book: нет counterparty matching, всегда есть ликвидность. |
| blockchain.ops.layer2_rollup | Layer 2 — Rollup Types | METHOD | Rollup: обрабатывает транзакции вне Ethereum → публикует compressed data + proof на L1. Optimistic Rollup (Arbitrum, Optimism): предполагает транзакции верны, 7-дневный challenge period. ZK-Rollup (zkSync, StarkNet): математическое доказательство валидности (validity proof, SNARK/STARK). Zkproof: не нужно оспаривать. Data availability: откат → L1 имеет данные для восстановления. | ZK faster finality но computationally intensive. Optimistic: проще реализовать. |
| blockchain.ops.nft_token_standard | NFT — ERC-721 vs ERC-1155 | METHOD | ERC-721: каждый token unique (одно NFT = один токен ID). ERC-1155: multi-token (один контракт = несколько типов, fungible + non-fungible в одном). Gas efficiency: ERC-1155 batch transfers. Metadata: URI указывает на JSON (name, description, image). On-chain vs off-chain metadata (IPFS — децентрализованный, centralized server — риск 404). | IPFS pinning: если никто не пинирует — метаданные исчезают. |
| blockchain.ops.cross_chain_bridge | Cross-Chain Bridge — Risk Vectors | METHOD | Мосты между блокчейнами: lock-and-mint (заблокировать на исходном → выпустить wrapped на целевом). Multichain/Wormhole bridge hack 2022: ~$325 млн (exploit в guardian multisig). Риски: smart contract bugs, validator compromise, admin key theft. Security model: optimistic (7-day challenge), zk-based (more secure). TVL (Total Value Locked): в мостах = концентрированная цель. | Multi-sig менее безопасен чем ZK proof для bridge security. |
| blockchain.ops.crypto_exchange_regulation | Crypto Exchange — KYC/AML | METHOD | KYC (Know Your Customer): identity verification при регистрации на CEX (Centralised Exchange). AML (Anti-Money Laundering): мониторинг подозрительных транзакций (FATF Travel Rule). VASP (Virtual Asset Service Provider): под FATF регулированием. SAR (Suspicious Activity Report): CEX обязаны подавать. MiCA (EU 2023): регулирование крипто-активов в ЕС (лицензия обязательна). | DEX: нет KYC (peer-to-peer) — регуляторное давление усиливается. |
| blockchain.ops.private_key_security | Private Key — Security Best Practices | METHOD | Безопасность приватного ключа: никогда не экспортировать в plaintext. Hardware wallet: offline generation + signing. Multi-signature (MultiSig): M-of-N подпись (например 2-of-3). Shamir's Secret Sharing: разбить seed на N частей, любые M достаточны. Air-gapped computer: подписание офлайн. Social engineering: самый частый вектор атаки (phishing). | $1B stolen 2023 via social engineering / phishing (Chainalysis report). |
| blockchain.ops.blockchain_scaling | Blockchain Scaling — Trilemma | METHOD | Трилемма блокчейна (Buterin): Decentralization + Security + Scalability — одновременно только два. Bitcoin: Security + Decentralization (ограниченная scalability). Solana: высокая Scalability + Security (меньше Decentralization — мощные ноды). Ethereum rollups: Layer1 = Security + Decentralization; Layer2 = Scalability. Sharding (Ethereum): параллельная обработка транзакций. | Нет идеального блокчейна: компромисс определяет use case. |
| blockchain.ops.merkle_tree | Merkle Tree — Transaction Verification | METHOD | Дерево Меркла: хэши транзакций попарно хэшируются до Merkle Root. Merkle Root включается в заголовок блока. Merkle proof: доказать что транзакция в блоке без скачивания всего блока (O(log n) операций). SPV (Simplified Payment Verification): лёгкие клиенты используют Merkle proofs. Bitcoin: бинарное дерево SHA-256. | Merkle proof: core компонент для cross-chain bridges и rollup data proofs. |
| blockchain.ops.stablecoin_types | Stablecoin — Types & Mechanisms | METHOD | Типы стейблкоинов: Fiat-backed (USDC, USDT): 1:1 с долларом в кастодии. Crypto-collateralized (DAI): сверхобеспечение ETH/WBTC (150%+), liquidation при падении. Algorithmic (Terra/LUNA был): без collateral, rebase/arbitrage mechanism — fragile (Terra крах 2022 $40 млрд). CBDC (Central Bank Digital Currency): государственный stablecoin. | Terra/LUNA collapse: death spiral — стейблкоин потерял привязку → sell pressure → collapse. |
| blockchain.ops.node_types | Full vs Light Node — Difference | METHOD | Full node (Bitcoin): скачивает всю цепочку (600+ GB), проверяет каждую транзакцию и блок независимо. Pruned full node: верифицирует но хранит только UTXO set (меньше места). Архивный узел: весь state history. Light node (SPV): только заголовки блоков, не верифицирует транзакции. Mining node (Bitcoin): + mempool + block creation. | Количество full nodes: показатель децентрализации. Больше = безопаснее. |
| blockchain.ops.dao_governance | DAO — Governance Mechanics | METHOD | DAO (Decentralized Autonomous Organization): управление через голосование токенхолдеров. Snapshot voting (off-chain, no gas), on-chain execution (Compound, Uniswap). Quorum: минимальный % токенов для валидного голосования. Timelock: задержка исполнения (позволяет exit). Governance attack: накопить токены → принять malicious proposal (Tornado Cash governance attack 2023). | Token voting = plutocracy (чем больше токенов, тем больше власти). |
| blockchain.ops.zero_knowledge_proof | Zero-Knowledge Proof — ZK-SNARK | METHOD | Доказательство с нулевым разглашением: prover доказывает знание без раскрытия. SNARK (Succinct Non-interactive ARgument of Knowledge): маленький proof (<1 КБ), быстрая верификация, trusted setup (toxic waste). STARK (Scalable Transparent ARgument of Knowledge): нет trusted setup, больший proof size, квантово-стойкий. Применение: zkRollup, private transactions (Zcash), identity verification. | Groth16 (SNARK): самый эффективный, используется Zcash, Tornado Cash. |
| blockchain.ops.defi_lending_liquidation | DeFi Lending — Collateral & Liquidation | METHOD | Протоколы кредитования (Aave, Compound): поставить залог (ETH) → занять (USDC). Health factor = collateral value / borrow value / liquidation threshold. HF<1 → ликвидация: liquidator погашает долг → получает залог + bonus (5-10%). Liquidation cascade: при резком падении цены → много ликвидаций → давление на цену. Interest rate: variable (supply/demand algo). | Gas при ликвидации: liquidator бот должен опережать других (MEV). |
| blockchain.ops.mempool_mev | Mempool — MEV (Maximal Extractable Value) | METHOD | MEV: прибыль от порядка включения/исключения транзакций в блок. Типы: front-running (вставить перед DEX swap → влиять на цену), sandwich attack, back-running, arbitrage, liquidation. Flashbots: MEV-boost (proposer-builder separation). Private mempool (MEV Blocker): отправить напрямую builder. | MEV в 2023: >$700 млн извлечено на Ethereum (Flashbots research). |
| blockchain.ops.bitcoin_utxo | Bitcoin UTXO — Transaction Model | METHOD | UTXO (Unspent Transaction Output) модель: каждый Bitcoin хранится в «монете» (UTXO). Транзакция: потребляет UTXOs (inputs) → создаёт новые (outputs). Coinbase transaction: блок-вознаграждение (первая транзакция в блоке). Privacy: coin-join = смешать UTXOs нескольких пользователей. UTXO set: полный список нетраченных выходов (Bitcoin Core хранит в память). | UTXO vs Account model (Ethereum): UTXO более privacy-preserving, сложнее для смарт-контрактов. |
