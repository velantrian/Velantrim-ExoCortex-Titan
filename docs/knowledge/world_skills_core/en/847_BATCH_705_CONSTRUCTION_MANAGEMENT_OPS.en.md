# BATCH 705: Construction Management — Project Coordination

**KnowledgeUnits:** 50
**Namespace:** `conmgmt.ops.*`
**Scope:** scheduling, cost_control, RFI, submittal, change_order, punchlist, closeout, BIM, safety_plan, procurement

| ID | KnowledgeUnit | Тип | Суть | Практический смысл |
|---|---|---|---|---|
| conmgmt.ops.cpm_schedule | CPM — Critical Path Method | METHOD | Метод критического пути (CPM): ES (Early Start), EF (Early Finish), LS (Late Start), LF (Late Finish). Float = LF - EF = LS - ES. Critical path: Float = 0. Forward pass: ES0 = 0, EF = ES + Duration. Backward pass: LF_last = EF_last, LS = LF - Duration. Successors: max(EF) → next ES. PDM (Precedence Diagramming Method): FS, SS, FF, SF dependencies. | TF (Total Float) отрицательный: проект уже опаздывает. |
| conmgmt.ops.earned_value_cpi | Earned Value — SPI & CPI | METHOD | Освоенная стоимость (EVA): PV (Planned Value), EV (Earned Value = % complete × BAC), AC (Actual Cost). SPI = EV/PV (Schedule Performance Index >1 = опережение). CPI = EV/AC (Cost Performance Index >1 = под бюджетом). Estimate at Completion (EAC) = BAC/CPI. TCPI = (BAC - EV) / (BAC - AC). | CPI <0.8 в середине проекта: статистически редко заканчивается >1.0. |
| conmgmt.ops.rfi_management | RFI — Request for Information | METHOD | RFI (Request for Information): подрядчик направляет архитектору/владельцу при неясности в документах. Обязательные элементы: номер RFI, описание вопроса, ссылка на чертёж/спецификацию, предложенный вариант решения, запрашиваемый ответ, дата. Response time: 5-10 рабочих дней (по договору). Log: отслеживание всех RFI. | Больше RFI = больше документация для потенциальных претензий (claims). |
| conmgmt.ops.submittal_log | Submittals — Process & Tracking | METHOD | Процесс согласования материалов (submittals): contractor собирает shop drawings, product data, samples → submits to architect → review → «Approved», «Approved as Noted», «Revise and Resubmit», «Rejected». Lead time: критично для procurement. Submittal schedule: перечень всех submittals + deadline. Log в Procore/Autodesk Construction Cloud. | «Approved as noted»: работа может продолжаться с условиями. «R&R»: нельзя заказывать до повторного утверждения. |
| conmgmt.ops.change_order_types | Change Orders — Types | METHOD | Изменение объёма работ: Change Order (CO) — согласованное изменение контрактной стоимости/срока. Construction Change Directive (CCD): немедленное выполнение до согласования стоимости (emergency). PCO (Potential Change Order): идентифицирован но не согласован. RFI resolving ambiguity: может создать CO claim. T&M (Time and Material): оплата по факту затрат + markup. | Dispute: неподписанный CO + выполненные работы = потенциальный claim. |
| conmgmt.ops.daily_report | Daily Report — Documentation | METHOD | Ежедневный отчёт подрядчика: weather conditions, temperature (concrete placement), manpower (roster by trade), equipment on site, work performed (description by location), visitors/inspections, issues/delays, materials delivered. Timestamp. Superintendent подписывает. AIA Document G711: форма Daily Report. | Daily reports: ключевой документ для delays и claims (доказательство фактических событий). |
| conmgmt.ops.punchlist_closeout | Punch List — Closeout Process | METHOD | Список незавершённых работ (punch list): составляется при Substantial Completion walk-through. Участники: owner, architect, contractor. Каждый пункт: описание, локация, ответственный, дата исправления. Certificate of Substantial Completion (AIA G704): официальный документ. After punch complete: Certificate of Final Completion. Lien waiver, as-built drawings, O&M manuals, warranties. | Substantial Completion: owner может занять здание + гарантийный период начинается. |
| conmgmt.ops.bim_clash_detection | BIM — Clash Detection | METHOD | BIM (Building Information Modeling): clash detection — Autodesk Navisworks, Revit. Types: hard clash (физическое пересечение = pipe через beam), soft clash (зазор нарушен), time (4D schedule clash — работы в одном месте одновременно). BCF (BIM Collaboration Format): файл с отметками о конфликтах. Resolve: координационные совещания (MEP coordination meetings). | MEP coordination до строительства: экономит $10-15/кв.фут изменений в поле. |
| conmgmt.ops.safety_site_plan | Safety Plan — Site Specific | METHOD | Проект организации производства работ по охране труда: SSSP (Site Specific Safety Plan). Разделы: fall protection (6 ft), excavation (>5 ft — shoring), scaffolding (10 ft), electrical (lockout), crane/lifting. Pre-task planning (PTP): ежедневно до работ. Toolbox Talk: еженедельные встречи по безопасности. Incident recording: OSHA 300 log. Near-miss reporting: without blame (learning culture). | OSHA 1926: construction safety standard (Federal, USA). |
| conmgmt.ops.subcontractor_procurement | Subcontractor Procurement — Prequalification | METHOD | Преквалификация субподрядчиков: финансовая устойчивость (EMR — Experience Modification Rate <1.0), backlog capacity, references (similar projects), insurance (GL, Workers Comp, Umbrella). Bid analysis: scope gaps, exclusions, alternates, value engineering. Award: не всегда lowest bid (qualifications matter). Subcontract agreement: back-to-back с general contract terms. | EMR >1.0: выше среднего по травматизму = red flag. |
| conmgmt.ops.site_logistics_plan | Site Logistics — Traffic & Material Flow | METHOD | Логистический план строительной площадки: входы/выходы, crane radius (no fly zones), material staging areas, worker parking, trailer locations, temporary utilities, waste management, safety perimeter. Updated каждый этап проекта. Tower crane: base + radius (conflicts with neighbours, airspace). Hoisting plan: lift plan (critical lifts >75% crane capacity). | Congested sites (urban): tight choreography = key to schedule. |
| conmgmt.ops.concrete_testing_field | Field Testing — Concrete QC | METHOD | Полевой контроль качества бетона: slump test (ASTM C143) — через 5 мин после замеса, temperature (C1064), air content (C231 pressure meter), unit weight (C138). Cylinders: 4" × 8" или 6" × 12", minimum 2 per load/50 CY. Break at 7 days (проверить тенденцию) + 28 days (design strength). Field cure vs lab cure: field = lower by 15-20%. | Перед заливкой: проверить что все инспекции пройдены (rebar, form, embed). |
| conmgmt.ops.lien_waiver_types | Lien Waivers — Conditional vs Unconditional | METHOD | Уступки права залога (lien waivers): Conditional Waiver on Progress Payment: действует только при получении оплаты. Unconditional Waiver on Progress Payment: безусловный. Conditional Final: при финальной оплате. Unconditional Final: полный отказ от претензий. Субподрядчики подают вместе с каждым платёжным заявлением. | Никогда не подписывать Unconditional до получения оплаты. |
| conmgmt.ops.cost_code_structure | Cost Codes — WBS Structure | METHOD | Структура стоимостного кодирования: WBS (Work Breakdown Structure) + Cost Account. Пример: 03-0000 (бетон) → 03-1100 (форм-снятие) → 03-1110 (стены, Grade). Job cost report: бюджет vs актуальный vs прогноз (EAC). Over/under: вести каждые 2 недели (не ждать конца месяца). Change orders: новые cost codes для отслеживания. | Cost code granularity: слишком подробно = сложно (100+ codes), слишком широко = нет контроля. |
| conmgmt.ops.payment_application_schedule_of_values | Payment Application — SOV | METHOD | Заявка на оплату (Application for Payment): G702/G703 (AIA). Schedule of Values (SOV): разбивка контрактной стоимости по компонентам. Percent complete (% complete) by line item. Stored materials: отдельная колонка. Retainage: удержание (обычно 10% до Substantial Completion, затем 5%). Notarized → submit to owner → 30 дней до оплаты (по договору). | Stored materials on site: проверка ownership (не должны быть encumbered). |
| conmgmt.ops.delay_analysis_methods | Delay Analysis — Types | METHOD | Методы анализа задержек: As-Planned vs As-Built (простейший, грубый). TIA (Time Impact Analysis): проанализировать влияние события на критический путь. Windows Analysis: разбить на периоды. MIP (Modified Impacted As-Planned): вставить delay events в baseline. Concurrent delay: если оба — owner и contractor задерживают → обычно нет компенсации (взаимный). Excusable: погода, owner-directed; Non-excusable: contractor failure. | «Pacing» delay: contractor замедляет в ответ на owner delay (спорный метод). |
| conmgmt.ops.quality_management_itp | Quality Management — ITP | METHOD | Программа контроля качества: ITP (Inspection and Test Plan) — список всех инспекций. Категории: H (Hold — работа не может продолжаться), W (Witness — inspector присутствует), R (Review — документация проверяется), I (Inspect — самопроверка). NCR (Non-Conformance Report): если работа не соответствует → описание, корректирующие действия, верификация. | ITP как договорное обязательство: нарушение = потенциальное требование от владельца. |
| conmgmt.ops.project_closeout_checklist | Closeout — Deliverables Checklist | METHOD | Закрытие строительного проекта: As-built drawings (record drawings), O&M manuals (operations & maintenance), warranties (equipment, roofing, waterproofing), attic stock (surplus material), commissioning reports, training records, certificates of occupancy, final lien waivers, punch list complete, final inspection approval. Certificate of Substantial Completion → Certificate of Final Completion → final payment. | O&M manual: ключевой для facility management (без него невозможно обслуживание). |
| conmgmt.ops.preconstruction_scope_gap | Preconstruction — Scope Gap Analysis | METHOD | Анализ пробелов в объёме до начала строительства: bid scoping (каждый subcontractor scope checked for gaps and overlaps). Gap: кто отвечает за utility piping между electrical and plumbing contractor? Buy-out meeting: GC + каждый sub → зафиксировать согласованный scope. Value engineering: экономия без снижения функции. Risk log: идентификация рисков + mitigation. | Scope gaps: основная причина change orders и disputes. |
| conmgmt.ops.commissioning_cx_process | Commissioning — Systems Verification | METHOD | Commissioning (Cx): верификация что системы здания работают согласно design intent. Cx Agent: независимый (от architect, contractor). OPR (Owner's Project Requirements): документ требований. BOD (Basis of Design). Pre-functional testing: компоненты. Functional testing: системы под нагрузкой. Seasonal commissioning: тестирование в summer/winter conditions. TAB (Testing, Adjusting, Balancing): воздушные/водяные системы. | LEED: enhanced commissioning = дополнительные кредиты. |
