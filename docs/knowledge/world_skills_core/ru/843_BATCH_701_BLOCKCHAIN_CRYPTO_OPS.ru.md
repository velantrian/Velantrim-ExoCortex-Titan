| blockchain.ops.pow_consensus | Доказательство работы — горная механика | METHOD | Доказательство работы (PoW): майнер подбирает nonce такой, что SHA-256(block_header) < target. Difficulty adjustment: каждые 2016 блоков (Bitcoin) → target изменяется чтобы среднее время блока = 10 мин. Hash rate: TH/s (TeraHash). 51% attack: контроль >50% hash rate → двойное расходование. ASIC: Application-Specific Integrated Circuit (только для SHA-256, неэффективен для других). | Энергопотребление Биткойн: ~150 ТВтч/год (2024 г.) ≈ как Польша. |
| blockchain.ops.pos_validator | Доказательство доли — Валидатор | METHOD | Доказательство доли (PoS): валидаторы «ставят» (stake) криптовалюту как залог. Выбор пропонента блока: взвешенный по stake. Slashing: наказание за двойное голосование / off-line. Ethereum validator: минимум 32 ETH stake. Epoch/slot: 12-сек слот, 32 слота = 1 эпоха (6.4 мин). Finality: после 2 эпох (checkpoint). | Доходность по стейкингу: 3-5% годовых (Ethereum). Нет фиксированного (рыночного). |
| blockchain.ops.hd_wallet_derivation | HD-кошелек — BIP32/39/44 | METHOD | Иерархический детерминированный кошелек (BIP32): одна сид-фраза → деревянные ключи. BIP39: мнемоника (12-24 слова → семя). BIP44: путь деривации m/44'/coin_type'/account'/change/address_index. Пример BTC: м/44’/0’/0’/0/0. Главный закрытый ключ → дочерний закрытый ключ → открытый ключ → адрес. Аппаратный кошелек (Ledger, Trezor): хранит семя в защищённой среде. | Seed phrase = доступ ко всем адресам. Никогда не онлайн, не на фото. |
| blockchain.ops.evm_smart_contract | EVM — Исполнение смарт-контрактов | METHOD | Ethereum Virtual Machine (EVM): стековая машина. Opcode: низкоуровневые инструкции. Solidity → bytecode → EVM execution. Gas: стоимость каждого opcode (SSTORE = 20 000 gas). Gas limit: max gas для транзакции. Base fee + priority fee (EIP-1559). Reentrancy attack: внешний вызов до обновления состояния → рекурсивное изъятие (DAO hack 2016). | Проверки-Эффекты-Взаимодействия: шаблон для предотвращения повторного входа. |
| blockchain.ops.defi_amm | DeFi — AMM и пулы ликвидности | METHOD | Автоматизированный маркет-мейкер (АММ): x × y = k (Uniswap v2). x и y — резервы токенов. Обмен: изменяет x и y, сохраняя k. Влияние на цену: чем больше своп относительно пула — тем выше. Непостоянные потери (IL): разница LP при расхождении цен против HODL. Концентрированная ликвидность (Uniswap v3): LP выбирает ценовой диапазон. Комиссии: 0,05% / 0,3% / 1%. | АММ vs книга заявок: совпадения контрагентов нет, ликвидность всегда есть. |
| blockchain.ops.layer2_rollup | Уровень 2 — Типы сводных данных | METHOD | Rollup: обрабатывает транзакции вне Ethereum → публикует compressed data + proof на L1. Optimistic Rollup (Arbitrum, Optimism): предполагает транзакции верны, 7-дневный challenge period. ZK-Rollup (zkSync, StarkNet): математическое доказательство валидности (validity proof, SNARK/STARK). Zkproof: не нужно оспаривать. Data availability: откат → L1 имеет данные для восстановления. | ZK более быстрая окончательность, но требует больших вычислительных ресурсов. Оптимистично: проще реализовать. |
| blockchain.ops.nft_token_standard | NFT — ERC-721 против ERC-1155 | METHOD | ERC-721: каждый токен уникален (одно NFT = один идентификатор токена). ERC-1155: мультитокен (один контракт = несколько типов, взаимозаменяемый + невзаимозаменяемый в одном). Эффективность использования газа: пакетная передача ERC-1155. Метаданные: URI указывает на JSON (имя, описание, изображение). Метаданные внутри сети и вне сети (IPFS — децентрализованный, централизованный сервер — риск 404). | IPFS pinning: если никто не пинирует — метаданные исчезают. |
| blockchain.ops.cross_chain_bridge | Крест-Цепной мост — векторы риска | METHOD | Мосты между помещениями: замок-и-мята (заблокировать на исходном → выпустить завернутым на целевом). Взлом моста Multichain/Wormhole 2022: ~$325 млн (эксплойт в Guardian Multisig). Риски: ошибки смарт-контрактов, компрометация валидатора, кража ключа администратора. Модель безопасности: оптимистичная (7-дневная задача), на основе zk (более безопасная). TVL (Общая стоимость заблокирована): в мостах = концентрированная цель. | Мультиподпись менее безопасна, чем доказательство ZK для безопасности моста. |
| blockchain.ops.crypto_exchange_regulation | Криптобиржа — KYC/AML | METHOD | KYC (Знай своего клиента): проверка личности при регистрации на CEX (Централизованная биржа). AML (Борьба с отмыванием денег): мониторинг подозрительных транзакций (Правило FATF Travel Rule). VASP (Поставщик услуг виртуальных активов): в соответствии с регулированием FATF. SAR (отчет о подозрительной активности): CEX рассчитывает подавать. MiCA (ЕС 2023): регулирование криптоактивов в ЕС (лицензия обязательна). | DEX: нет KYC (peer-to-peer) — регуляторное давление усиливается. |
| blockchain.ops.private_key_security | Закрытый ключ — лучшие практики безопасности | METHOD | Безопасность приватного ключа: никогда не экспортировать в plaintext. Hardware wallet: offline generation + signing. Multi-signature (MultiSig): M-of-N подпись (например 2-of-3). Shamir's Secret Sharing: разбить seed на N частей, любые M достаточны. Air-gapped computer: подписание офлайн. Social engineering: самый частый вектор атаки (phishing). | 1 миллиард долларов украден в 2023 году с помощью социальной инженерии/фишинга (отчет Chainaанализа). |
| blockchain.ops.blockchain_scaling | Масштабирование блокчейна — Трилемма | METHOD | Трилемма подвеса (Бутерин): Децентрализация + Безопасность + Масштабируемость — одновременно только два. Биткойн: Безопасность + Децентрализация (ограниченная масштабируемость). Солана: высокая масштабируемость + безопасность (меньше децентрализации — мощные ноды). Объединения Ethereum: Уровень 1 = Безопасность + Децентрализация; Уровень 2 = Масштабируемость. Шардинг (Ethereum): параллельная обработка транзакций. | Нет идеального блокчейна: компромисс определяет use case. |
| blockchain.ops.merkle_tree | Дерево Меркла — проверка транзакции | METHOD | Дерево Меркла: хэши транзакций попарно хэшируются до Merkle Root. Merkle Root включается в заголовок блока. Merkle proof: доказать что транзакция в блоке без скачивания всего блока (O(log n) операций). SPV (Simplified Payment Verification): лёгкие клиенты используют Merkle proofs. Bitcoin: бинарное дерево SHA-256. | Доказательство Меркла: основной компонент для перекрестных цепочек и доказательств сводных данных. |
| blockchain.ops.stablecoin_types | Стейблкоин — типы и механизмы | METHOD | Типы стейблкоинов: Фиатные валюты (USDC, USDT): 1:1 с долларом в кастодии. Крипто-обеспечение (DAI): сверхобеспечение ETH/WBTC (150%+), ликвидация при падении. Алгоритмический (Terra/LUNA был): без залога, механизм ребаза/арбитража — хрупкий (Terra крах 2022 $40 млрд). CBDC (цифровая валюта Центрального банка): государственный стейблкоин. | Крах Terra/LUNA: спираль смерти — стейблкоин потерял привязку → давление продажи → коллапс. |
| blockchain.ops.node_types | Полный и легкий узел — разница | METHOD | Full node (Bitcoin): скачивает всю цепочку (600+ GB), проверяет каждую транзакцию и блок независимо. Pruned full node: верифицирует но хранит только UTXO set (меньше места). Архивный узел: весь state history. Light node (SPV): только заголовки блоков, не верифицирует транзакции. Mining node (Bitcoin): + mempool + block creation. | Количество full nodes: показатель децентрализации. Больше = безопаснее. |
| blockchain.ops.dao_governance | ДАО — Механика управления | METHOD | DAO (Децентрализованная автономная организация): управление через голосование токенхолдеров. Моментальное голосование (вне сети, без газа), выполнение в сети (Compound, Uniswap). Кворум: создать % токенов для действительного голосования. Timelock: задержка исполнения (позволяет выход). Атака управления: накопить токены → Принять вредоносное предложение (атака управления Tornado Cash 2023). | Token voting = plutocracy (чем больше токенов, тем больше власти). |
| blockchain.ops.zero_knowledge_proof | Доказательство с нулевым разглашением — ZK-SNARK | METHOD | Доказательство с нулевым разглашением: доказывающий показывает знание без раскрытия. СНАРК (Краткий неинтерактивный ARgument of Knowledge): маленькое доказательство (<1 КБ), быстрая верификация, доверенная установка (токсичные отходы). STARK (Scalable Transparent ARgument of Knowledge): нет доверенной настройки, больший размер доказательства, квантово-стойкий. Применение: zkRollup, частные транзакции (Zcash), проверка личности. | Groth16 (SNARK): самый эффективный, используется Zcash, Tornado Cash. |
| blockchain.ops.defi_lending_liquidation | DeFi-кредитование — обеспечение и ликвидация | METHOD | Протоколы кредитования (Aave, Compound): поставить залог (ETH) → занять (USDC). Liquidation cascade: при резком падении цены → много ликвидаций → давление на цену. Interest rate: variable (supply/demand algo). | Gas при ликвидации: liquidator бот должен опережать других (MEV). |

Типы: опережение (вставить перед свопом DEX → влияние на цену), сэндвич-атака, отставание, арбитраж, ликвидация. Флешботы: MEV-boost (разделение предлагающего и создателя).
