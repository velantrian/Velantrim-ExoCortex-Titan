| compnet.ops.ospf_areas | OSPF — Проектирование территорий | METHOD | OSPF (сначала открывайте кратчайший путь): протокол состояния канала. Области: Area 0 (Backbone), остальные области подключаются через ABR (Area Border Router). Типы маршрутизаторов: IR (внутренний маршрутизатор), ABR, ASBR (граничный маршрутизатор автономной системы). Типы LSA: Тип 1 (Маршрутизатор), 2 (Сеть), 3 (Сводный), 4, 5 (Внешний). Алгоритм SPF: Дейкстра. | Тупиковая область OSPF: LSA типа 5 не разрешены. Совсем коротко: только Тип 1+2+3. |
| compnet.ops.vlan_trunking | VLAN — транкинг 802.1Q | METHOD | VLAN (Virtual LAN): логическое разделение Ethernet. Тег 802.1Q: 4-байтовый в кадре Ethernet (12 бит VLAN ID = 4094 VLAN). Собственный VLAN: без тега на транке. Порт доступа: один VLAN. Магистральный порт: несколько VLAN. Маршрутизация между VLAN: маршрутизатор на адаптере (субинтерфейсы) или коммутатор уровня 3 (SVI). | Default VLAN 1: небезопасно оставлять для данных. |
| compnet.ops.tcp_three_way | TCP — трехстороннее рукопожатие | METHOD | TCP 3-шаговое рукопожатие: SYN → SYN-ACK → ACK. SYN: SEQ = ISN (начальный порядковый номер). SYN-ACK: SEQ = ISN сервера, ACK = ISN клиента+1. ACK: завершение. Конечный автомат: СЛУШАТЬ → SYN_RECEIVED → ESTABLISHED. Окно перегрузки (cwnd). Полузакрытие: одна сторона закрывает (FIN-WAIT). | TIME_WAIT: 2×MSL (максимум 4 мин) предотвращает коллизии с новым соединением. |
| compnet.ops.sdn_openflow | SDN — протокол OpenFlow | METHOD | Программно-определяемая сеть (SDN): отделение плоскости управления от плоскости данных. Контроллер (логическое): Рю, ОНОС, OpenDaylight. Переключатель (плоскость данных): OpenFlow (1.0, 1.3). Поля соответствия: MAC-адрес назначения, IP, VLAN, Порт. Действия: переслать, удалить, изменить. Таблица расхода: набор правил. Разделение: большей программируемости. | OpenFlow против NETCONF/RESTCONF: OpenFlow = плоскость данных низкого уровня, NETCONF = управление конфигурацией. |
| compnet.ops.wireless_802_11 | Wi-Fi — стандарты 802.11 | METHOD | Стандарты Wi-Fi: 802.11a/g: 54 Мбит/с. 802.11n (Wi-Fi 4): до 600 Мбит/с, MIMO. 802.11ac (Wi-Fi 5): 6,9 Гбит/с, MU-MIMO, только 5 ГГц. 802.11ax (Wi-Fi 6): 9,6 Гбит/с, OFDMA, окраска BSS, TWT. Wi-Fi 6E: диапазон 6 ГГц. Wi-Fi 7 (802.11be): 46 Гбит/с, MLO. CSMA/CA: протокол доступа (в отличие от CSMA/CD в Ethernet). | OFDMA (Wi-Fi 6): разделяет канал между устройствами (улучшает Dense environments). |
| compnet.ops.spanning_tree_rstp | Связующее дерево — RSTP | METHOD | RSTP (Rapid Spanning Tree Protocol, 802.1w): конвергенция <1 сек (против STP 30-50 сек). Роли порта: корневой, назначенный, альтернативный, резервный. Состояния порта: Отбрасывание, Обучение, Пересылка. Механизм предложения-договора: быстрая синхронизация. MSTP (множественный STP): разные технологии STP для разных VLAN. | STPloop: сеть перегружается от broadcast storm. STP предотвращает. |
| compnet.ops.multicast_pim | Многоадресная рассылка — ПИМ | METHOD | IP Multicast: один источник → несколько получателей. IGMP: хост → подключение/выход маршрутизатора. PIM (независимая от протокола многоадресная рассылка): плотный режим (расширение + сокращение) и разреженный режим (общее дерево + SPT). Точка встречи (RP): точка встречи. Многоадресная рассылка с учетом источника (SSM): PIM SSM. IGMP snooping: переключатель понимает многоадресные группы. | Диапазон IP-адресов многоадресной рассылки: 224.0.0.0/4 (класс D). |
| compnet.ops.nat_pat_detail | NAT — типы и реализация | METHOD | NAT (трансляция сетевых адресов): Статический NAT: постоянный 1:1. Динамический NAT: пул адресов. PAT (трансляция/перегрузка адресов портов): много:1 (с портами). CGNAT (операторский уровень): уровень интернет-провайдера. ALG (шлюз прикладного уровня): для SIP, FTP (меняет полезную нагрузку). Привязка NAT: внутренний хост → общедоступный IP → назад. | DNS ALG: необходим для разделения DNS с NAT. |
| compnet.ops.network_security_ids | Сетевая безопасность — IDS/IPS | METHOD | Обнаружение/предотвращение вторжений (IDS/IPS): На основе подписи: оригинальные узоры (быстрое). На основе аномалий: отклонение от нормы (находит новые атаки). SNORT: IPS с открытым исходным кодом. Встроенный (IPS) или пассивный (IDS). Брандмауэр следующего поколения (NGFW): DPI + осведомленность о приложениях + проверка SSL. Зик/Бро: структура сетевого анализа. | Deep Packet Inspection (DPI): смотрит внутрь пакета (не только заголовки). |
| compnet.ops.cloud_vpc | Облачные сети — VPC | METHOD | Виртуальное частное облако (VPC): изолированная сеть в облаке. Подсети: общедоступные (маршрут IGW) и частные (шлюз NAT). Группы безопасности: с сохранением состояния (разрешения). Сетевые списки управления доступом: без сохранения состояния (разрешить/запретить для каждого правила). Пиринг VPC: связь VPC. Транзитный шлюз: ступица для многих VPC. Direct Connect/ExpressRoute: выделенный канал. | Группа безопасности: нет явного запрета → запрет по умолчанию (NACL = явный). |
| compnet.ops.network_automation_ansible | Автоматизация сети — Ansible | METHOD | Сетевая автоматизация с Ansible: Playbooks (YAML). Сетевые модули: ios_command, eos_config, junos_config. Инвентарь: файл хостов или динамический. Идемпотент: повторные запуски безопасны. Шаблоны (Jinja2): генерация конфигов. NAPALM: автоматизация сетей различных поставщиков. Ansible AWX/Tower: графический интерфейс + планирование. | Инфраструктура как код (IaC): выражение как код = версионность + воспроизводимость. |
| compnet.ops.ntp_clock_sync | NTP — синхронизация времени | METHOD | Протокол сетевого времени (NTP): уровень 0 (атомные часы) → уровень 1 (прямое подключение) → уровень 2 → ... → уровень 16 (несинхронизация). Клиент синхронизируется с NTP-сервером. Точность: <1 мс (LAN), <10 мс (WAN). PTP (IEEE 1588): точнее (наносекунды). Второй шаг: осложнение для NTP. | Правильное время: обязательно для TLS certificates, logs, Kerberos. |
| compnet.ops.dhcp_operation | DHCP — типы сообщений | METHOD | Операция DHCP: DORA (Обнаружение, Предложение, Запрос, Подтверждение). UDP: клиент 68, сервер 67. Срок аренды: клиент запрашивает продление при 50% истечения. Агент ретрансляции DHCP: для DHCP между VLAN. Отслеживание DHCP: безопасность (блокирует несанкционированные DHCP-серверы). Динамическая проверка ARP (DAI): связанный механизм защиты. | Атака с голоданием DHCP: заполнить пул DHCP → DoS. DHCP отслеживает свой собственный. |
| compnet.ops.mpls_vpn_l3 | MPLS L3 VPN — Архитектура | METHOD | MPLS L3 VPN: PE (граница поставщика) + P (ядро поставщика) + CE (граница клиента). VRF (Виртуальная маршрутизация и пересылка): изолированные таблицы маршрутизации. MP-BGP: обмен VPN-маршрутами между PE. Route Distinguisher (RD): уникализация префиксов. Route Target (RT): данные в лучших VRF. Стек из двух меток: транспортная метка + метка VPN. | VRF lite: L3 VPN без MPLS (на одном маршрутизаторе). |
| compnet.ops.tcp_optimization | TCP — настройка производительности | METHOD | Оптимизация TCP: Масштабирование окна (RFC 7323): окно >65535 байт. Временные метки: измерение RTT + PAWS (защита от обертывания). SACK (Выборочное подтверждение): эффективное восстановление. ECN (Explicit Congestion Notification): не дожидаться падения. Размеры TCP-буфера: net.core.rmem_max, net.ipv4.tcp_rmem. | TCP Offload Engine (TOE): перенести TCP на NIC (снижает CPU нагрузку). |
| compnet.ops.network_monitoring_snmpv3 | Мониторинг сети — SNMPv3 | METHOD | Безопасность SNMPv3: Аутентификация: HMAC-MD5 или HMAC-SHA. Шифрование: DES или AES (предпочтительное). USM (модель безопасности на основе пользователя). Контроль доступа на основе представлений (VACM). Пользователи SNMPv3: authPriv (аутентификация + шифрование), authNoPriv, noAuthNoPriv. Назначение ловушки: SNMPv3 сообщает (подтверждение). | NetFlow/sFlow/IPFIX: трафик аналитика (дополнение к SNMP). |
| compnet.ops.bgp_route_policy | BGP — Политика маршрутизации | METHOD | Манипулирование политикой BGP: Карты маршрутов: match + set (применяется при импорте/экспорте). Списки префиксов: фильтрация по префиксу IP. ACL AS-path: фильтрация по AS-пути. Сообщество: маркировка для политики. Манипулирование атрибутами: локальное предпочтение, MED, вес (только локальный эффект). Добавление AS-пути: удлинение → сигнализация менее предпочтительный путь. | iBGP: Full Mesh или Route Reflector (RR) для масштабируемости. |
| compnet.ops.vxlan_overlay | VXLAN — наложение центров обработки данных | METHOD | VXLAN (виртуальная расширяемая локальная сеть): протокол наложения (RFC 7348). 24-битный VNI (идентификатор виртуальной сети): 16 млн VLAN. Инкапсуляция: исходный кадр → заголовок UDP (порт 4789). VTEP (конечная точка туннеля VXLAN): конечные коммутаторы. BGP EVPN: плоскость управления для VXLAN. Мультитенантное наложение. | VXLAN против MPLS: VXLAN = на основе UDP (более простой), MPLS = на основе меток (более зрелый). |
| compnet.ops.zero_trust_network | Сети с нулевым доверием | METHOD | Доступ к сети с нулевым доверием (ZTNA): не доверять сети по умолчанию. Принципы: проверка личности + устройство + доступ. Микросегментация: каждая рабочая нагрузка изолирована. Программно-определяемый периметр (SDP). BeyondCorp (Google): реализация без VPN. SaaS + ориентированный на идентификацию: SASE (Secure Access Service Edge). | «Доверяй, но проверяй» → «Никогда не доверяй, всегда проверяй». |
