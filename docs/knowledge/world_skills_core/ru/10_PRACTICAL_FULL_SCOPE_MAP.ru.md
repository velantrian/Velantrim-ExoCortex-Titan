# 🏭 Practical Full Scope Map — полный состав практического слоя

**Язык:** русский  
**Статус:** рабочая карта v0.1  
**Назначение:** не потерять смысл при сборе 20 000+ units.  
**Суть:** практическая база должна покрывать не только дороги, бетон и доменные печи, а весь человеческий слой производства, быта, ремёсел, здоровья, еды, одежды, жилья, инструментов, искусства, ремонта и услуг.

---

## 🧠 Главный вывод

Ты прав: если Velantrim должен отвечать на вопросы вроде:

```text
как делают кирпич?
как устроена доменная печь?
как делают одежду?
как делают лекарство?
как делают еду?
как строят крышу?
как работают с деревом?
как делают карандаш, ручку, краску, бумагу?
как делают мотор, насос, батарею, стекло, пластик?
```

то одной "инвариантной науки" недостаточно.

Нужен отдельный слой:

```text
PRACTICAL CIVILIZATION CORE
```

Он должен хранить:

- сырьё;
- материалы;
- оборудование;
- этапы процесса;
- условия;
- контроль качества;
- failure modes;
- safety;
- бытовые и промышленные варианты;
- связи с физикой, химией, биологией, математикой и логикой.

## 🔎 Откуда берём карту покрытия

Каркас надо брать не из головы, а из классификаций деятельности:

| Источник | Что даёт |
|---|---|
| `ISIC Rev.4` | международная классификация видов экономической деятельности |
| `NAICS 2022` | подробная production-oriented классификация отраслей |
| `NACE Rev.2` | европейская классификация деятельности |
| `OECD/FORD` | научные области и R&D |
| `standards/manuals` | ISO/IEC/ASTM/ASM/WHO/FAO и отраслевые справочники |

Эти классификации важны потому, что они показывают: человеческая практика — это не только заводы. Это сельское хозяйство, одежда, еда, жильё, вода, медицина, ремонт, искусство, транспорт, связь, услуги, образование и управление.

## 📦 Формат Practical Process Unit

Для практической базы обычного `statement` мало. Нужен процессный формат:

```json
{
  "id": "process.ceramics.brick_firing",
  "domain": "materials.ceramics.brick",
  "type": "PROCESS",
  "purpose": "Получить прочный керамический кирпич из подготовленной глины.",
  "inputs": ["clay", "water", "temper additives"],
  "equipment": ["mixer", "mold_or_extruder", "dryer", "kiln"],
  "steps": [
    "подготовить сырьё",
    "смешать с водой",
    "сформовать",
    "высушить",
    "обжечь",
    "охладить",
    "проверить качество"
  ],
  "conditions": ["контроль влажности", "режим сушки", "температурный профиль обжига"],
  "failure_modes": ["трещины", "недообжиг", "пережог", "деформация"],
  "quality_checks": ["размер", "прочность", "водопоглощение", "звук/трещины"],
  "safety": ["пыль", "высокая температура", "движущиеся механизмы"],
  "links": ["chem.ceramic", "phys.thermal_expansion", "eng.kiln"]
}
```

## 🧠 Главное правило: practical ≠ recipe без контекста

Практическая база не должна выдавать опасные инструкции без рамки.

Для каждого процесса нужны:

```text
что делаем
зачем
из чего
каким оборудованием
какие этапы
какие условия
какие ошибки
как проверить качество
какие риски
что нельзя делать
какая наука под этим лежит
```

То есть Velantrim должен не просто отвечать:

> "кирпич обжигают"

А отвечать:

> "кирпич — это процесс сырьё → формование → сушка → обжиг → контроль. Главные причины брака: влажность, неправильная сушка, температурный режим, состав глины. Риски: пыль, тепло, оборудование."

## ✅ Итог

Практический слой должен покрывать всю человеческую цивилизацию как систему действий:

```text
природа → сырьё → материал → инструмент → процесс → продукт → использование → ремонт → отходы → безопасность
```

Это и есть правильная карта для 20 000+ units.
