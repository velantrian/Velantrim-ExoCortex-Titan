# BATCH 673: Access Control — Biometric & Smart Systems

**KnowledgeUnits:** 5
**Namespace:** `accesscontrol.ops.*`
**Scope:** biometric, facial_recognition, fingerprint, credential, controller, integration, audit_trail, access_levels

| ID | KnowledgeUnit | Тип | Суть | Практический смысл |
|---|---|---|---|---|
| accesscontrol.ops.biometric_enrollment | Биометрическая регистрация — лучшие практики | METHOD | Регистрация биометрических данных. Fingerprint: 3 регистрации с одного пальца (разные углы), добавить резервный (левый+правый). False Reject Rate (FRR): если слишком высокий — повторная регистрация. Сухая кожа, мозоли, порезы: lower quality template (дополнительные registration fingers). Facial recognition: нейтральное выражение, разное освещение (indoor/outdoor registration). GDPR: биометрия = special category data (явное согласие, срок хранения, right to delete). | FAR (коэффициент ложного принятия) 0,0001% по сравнению с компромиссом FRR. |
| accesscontrol.ops.wiegand_osdp_protocols | Протоколы — Wiegand против OSDP | METHOD | Протоколы передачи данных считывателей. Wiegand (устаревший): одностороннее (reader → controller), нет шифрования (уязвим к sniffing), нет tamper monitoring, max длина кабеля 150 м. OSDP v2 (Open Supervised Device Protocol): двухсторонний, AES-128 шифрование, cable supervision (обрыв обнаруживается), до 1.2 км кабеля, LED/buzzer control с controller. Переход: OSDP становится стандартом (FICAM, SIA). RS-485 физический уровень (2-wire). | Wiegand intercept: записать data и replay = несанкционированный доступ. |
| accesscontrol.ops.access_schedule_holidays | Расписания доступа — часовые пояса и праздники | METHOD | Управление расписаниями доступа. Time zones (TZ): период доступа (Mon-Fri 8:00-18:00). Holiday schedule: список дат (override для holidays — закрыт или ограниченный доступ). Cardholder assignment: каждому пользователю один или несколько access levels (AL). AL = TZ + door combination. Первый день rule: access от следующего дня после issue карты (некоторые системы). Временный доступ: expiry date на карте. Anti-passback (APB): нельзя войти дважды без выхода (предотвращение tailgating). | Мягкий APB: предупреждение но пускает. Жёсткий APB: блокирует. |
| accesscontrol.ops.audit_trail_reporting | Контрольный журнал — ведение журнала событий и отчетность | METHOD | Журнал событий системы контроля доступа. Каждое событие: временная метка, дверь, идентификатор владельца карты, тип события (доступ/отказ, взломанная дверь, открытая подпорка). Срок хранения: минимум 90 дней (некоторые — 2 года). Отчеты: ежедневная активность, доступ в нерабочее время, отклоненные попытки, история конкретного человека. Предупреждения: взломанная дверь (тревога без предъявления карты), подпертая дверь (дверь открыта >X сек), нарушение запрета обратного прохода. Интеграция с HR: прекратить доступ при представлении (автоматически через HR-систему). | Forensic: после инцидента — audit trail ключевой документ. |
| accesscontrol.ops.visitor_management_portal | Управление посетителями — Портал самообслуживания | METHOD | Управление гостями. Pre-registration: хост регистрирует посетителя онлайн (name, ID, purpose, host, time window). Посетитель на входе: смартфон check-in (QR код из email) или reception: scan ID (driver's license OCR), print badge (включает QR). Badge: фото, имя, дата, зоны доступа. Временная карта/QR: ограниченный доступ только в разрешённые зоны. Escort required: если sensitive zone. Departure: check-out (badge return). Host notification: SMS/email. Watchlist: проверка против deny list. | Без системы: неизвестно кто в здании (fire evacuation challenge). |
