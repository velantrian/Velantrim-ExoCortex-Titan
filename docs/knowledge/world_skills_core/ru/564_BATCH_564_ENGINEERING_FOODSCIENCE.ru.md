| engineering.environmental.air_pollution | Контроль загрязнения воздуха | METHOD | Твёрдые частицы (PM10, PM2.5): циклоны (центробежное), электрофильтры (ESP — коронный разряд, 99%+), рукавные фильтры. | engineering.environmental.soil_remediation | Восстановление почвы и подземных вод | METHOD | Pump-and-treat (откачка + очистка на поверхности — медленно). Permeable reactive barriers (Fe⁰ — восстановительное дехлорирование). |
| engineering.environmental.lca | Оценка жизненного цикла (LCA) | METHOD | Рамки ISO 14040/14044: цель/область → инвентаризационный анализ (все входы/выходы) → оценка воздействий (категории воздействия: ПГП, эвтрофикация, подкисление, токсичность для человека, разрушение озонового слоя) → интерпретация. От колыбели до ворот против колыбели до могилы. | ReCiPe, TRACI — методы категоризации воздействия. Функциональная единица — ключ к честному сравнению (бумажный пакет = 1 поход в магазин, пластиковый — 4 требует для равенства функционально!). |
| engineering.environmental.circular_economy | Круговая экономика | MODEL | Р-иерархия: Отказаться, Уменьшить, Повторное использование, Ремонт, Восстановить, Восстановить, Перепрофилировать, Переработать, Восстановить (энергия). | engineering.systems.v_model | Системная инженерия — V-модель | METHOD | Требования → архитектура → детальный дизайн → реализация → юнит-тесты → интеграционные → системные → валидация. Verification (правильно ли построили?) vs Validation (то ли построили?). | Аэрокосмическая и оборонная промышленность. Traceability matrix (каждое требование → компонент → тест). |
| engineering.systems.requirements | Разработка требований | METHOD | Функциональные (что система делает) и нефункциональные (как: надёжность 99.95%, latency <100ms). Stakeholder analysis. Use cases, user stories. Требования должны быть SMART, verifiable, atomic. | Большинство провалов проектов — плохие требования (размытые, неполные, противоречивые). Ошибка в требованиях на этапе дизайна стоит в 10-100 раз дешевле, чем после развёртывания. |
| engineering.systems.reliability | Инженерия надежности и FMEA | METHOD | FMEA (Failure Mode and Effects Analysis): список отказов → их последствия → серьёзность (S), вероятность (O), обнаружимость (D) → RPN = S×O×D. Анализ дерева отказов (Fault Tree Analysis — булева логика отказов). | Резервирование (избыточность): N+1, 2N. MTBF (среднее время наработки на отказ) и MTTR (среднее время на ремонт) → Доступность = MTBF/(MTBF+MTTR). |
| food_science.pasteurization | Пастеризация и стерилизация | METHOD | Пастеризация: уничтожение вегетативных патогенов (молоко: 72°C/15с HTST — Coxiella burnetii). D-value (время для 1-log уменьшения при данной T), z-value (ΔT для 10× изменения D). | UHT молоко (135-150°C/2-5 сек → асептическая упаковка → shelf life 6-9 мес без холодильника). | food_science.haccp | ХАССП — Анализ рисков | CONTROL | 7 принципов ККТ (критических контрольных точек): анализ опасностей (био, хим, физ) → определение ККТ → критические пределы (T, время, pH, a_w) → мониторинг → коррекции → верификация → документация. | a_w (активность воды): <0.85 — нет роста бактерий, <0.6 — всё останавливается (сухофрукты, мёд). pH <4.6 — нет C. botulinum (консервирование). |
