# 🌾 Agro, Textile, Industry, Economy & Law Scope

**Язык:** русский  
**Статус:** рабочая карта v0.1  
**Назначение:** расширить Practical Civilization Core тем, что люди выращивают, используют как сырьё, перерабатывают в материалы, применяют в медицине/красках/одежде/строительстве, а также тем, как строятся предприятия, работают фабрики, экономика, финансы, международная торговля и международное право.

---

## 🧠 Почему это отдельный слой

Практическое знание начинается не на заводе.

Оно часто начинается так:

```text
растение / животное / минерал / вода / земля
  → сырьё
  → обработка
  → материал
  → продукт
  → рынок
  → торговля
  → право
  → использование человеком
```

Если не включить этот слой, Velantrim сможет говорить о моторе или дороге, но будет слабее понимать:

- откуда берётся хлопок для одежды;
- какие растения дают волокно, красители, масла, лекарства;
- как культура выращивается и перерабатывается;
- как строятся заводы и фабрики;
- как предприятие считает деньги, закупки, себестоимость, прибыль;
- как работает международная торговля и право.

## 🌿 Medicinal herbs — правило безопасности

Лекарственные растения нельзя хранить как "лечит X" без доказательности.

Правильный формат:

```text
растение
  → используемая часть
  → традиционное применение
  → известные активные вещества
  → evidence level
  → возможный риск
  → противопоказания
  → взаимодействия
  → source tier
```

Пример формата:

```json
{
  "id": "plant.medicinal.chamomile",
  "domain": "botany.medicinal_plants",
  "type": "MATERIAL_SOURCE",
  "plant": "Matricaria chamomilla",
  "used_part": "flowers",
  "uses": ["tea", "cosmetic", "traditional mild digestive use"],
  "active_compounds": ["flavonoids", "essential oils"],
  "evidence_level": "mixed_or_limited_for_many_claims",
  "risks": ["allergy possible"],
  "truth_status": "SUPPORTED"
}
```

Важно:

> Velantrim может хранить знания о травах, но не должен превращаться в медицинского советчика без safety, источников и ограничений.

## 🏭 Как описывать предприятие / завод / фабрику

Для завода нужна не одна запись, а структура:

```text
FactoryUnit
  ├── product
  ├── raw_materials
  ├── utilities: water / power / heat / compressed air
  ├── process_flow
  ├── equipment
  ├── buildings
  ├── workers / skills
  ├── safety
  ├── emissions / waste
  ├── quality control
  ├── maintenance
  ├── logistics
  ├── finance
  └── legal permits
```

Пример:

```json
{
  "id": "factory.textile.cotton_spinning_mill",
  "type": "FACTORY_UNIT",
  "product": "cotton yarn",
  "inputs": ["cotton fiber", "electricity", "water for humidification"],
  "process_flow": [
    "fiber opening",
    "cleaning",
    "carding",
    "drawing",
    "roving",
    "spinning",
    "winding",
    "quality control"
  ],
  "equipment": ["opener", "carding machine", "drawing frame", "spinning frame", "winder"],
  "quality_checks": ["yarn count", "strength", "evenness", "contamination"],
  "safety": ["dust", "moving machinery", "noise", "fire risk"],
  "links": ["plant.cotton", "textile.spinning", "finance.unit_cost"]
}
```

## 💰 Экономика и финансы — что нужно системе

Система должна понимать не только "как сделать", но и:

```text
можно ли это произвести?
сколько стоит?
какие ресурсы нужны?
где узкое место?
какой риск?
какая маржа?
как работает рынок?
какие правила торговли?
```

### Финансовые units

| ID / тема | Суть |
---|---|
| `finance.revenue` | выручка = деньги от продажи |
| `finance.cogs` | себестоимость проданных товаров |
| `finance.gross_margin` | валовая маржа = выручка - COGS |
| `finance.opex` | операционные расходы |
| `finance.capex` | капитальные вложения |
| `finance.depreciation` | распределение стоимости актива по сроку службы |
| `finance.cash_flow` | движение денег важнее бухгалтерской прибыли для выживания |
| `finance.working_capital` | деньги, связанные в запасах, дебиторке, кредиторке |
| `finance.break_even` | точка безубыточности |
| `finance.unit_economics` | прибыльность одной единицы продукта/клиента |

### Economics units

| Тема | Суть |
|---|---|
| спрос / предложение | как цена и количество связаны с рынком |
| эластичность | насколько спрос/предложение реагирует на цену |
| специализация | люди/страны производят то, где эффективнее |
| сравнительное преимущество | торговля выгодна даже при абсолютном преимуществе одной стороны |
| инфляция | общий рост цен |
| процентная ставка | цена времени и риска денег |
| productivity | output на input |
| externalities | побочные эффекты на третьих лиц |
| public goods | блага, где трудно исключить и нет конкуренции |
| market failure | когда рынок сам не даёт хорошего результата |

## 🚢 Международная торговля

| Тема | Что хранить |
|---|---|
| импорт / экспорт | поток товаров через границы |
| тариф | налог на импорт/экспорт |
| квота | количественное ограничение |
| санкции | правовые ограничения торговли |
| Incoterms | кто отвечает за перевозку, риск, страхование |
| customs | таможенные процедуры |
| bill of lading | документ перевозки груза |
| letter of credit | банковский механизм оплаты |
| exchange rate risk | риск изменения валютного курса |
| rules of origin | происхождение товара для тарифов/соглашений |
| trade compliance | соблюдение правил, санкций, экспортного контроля |

## ⚖️ Международное право

Международное право не хранить как "одна простая истина".

Нужно различать:

```text
treaty
customary law
jurisdiction
sovereignty
arbitration
trade law
human rights
environmental law
maritime law
intellectual property
labor standards
dispute settlement
```

Для каждого правила нужны:

- источник;
- юрисдикция;
- стороны;
- дата;
- применимость;
- исключения;
- enforcement;
- связь с торговлей/финансами/производством.
