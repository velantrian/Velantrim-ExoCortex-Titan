| qualitymgmt.ops.iso9001_context | ISO 9001:2015 — Ключевые изменения | METHOD | Основные изменения ISO 9001:2015 от 2008 года: Контекст организации (раздел 4). Мышление, основанное на рисках (управление рисками во всем). Акцент на лидерстве (больший фокус Top Management). Управление знаниями. Нет обязательного Руководства по качеству. Процессуальный подход усилен. Структура высокого уровня (HLS): совместима с другими стандартами ISO. | PDCA: «Планируй-Делай-Проверяй-Действуй» = основа ISO 9001. |
| qualitymgmt.ops.sipoc_process_map | SIPOC — Картирование процессов | METHOD | SIPOC: Suppliers, Inputs, Process, Outputs, Customers. Инструмент для определения границ процесса. Process steps: 4-7 на высоком уровне. Customers: внутренние + внешние. Входные требования и выходные требования. Value Stream Map (VSM): более детальный. | SIPOC первоначальный шаг в DMAIC Define фазе. |
| qualitymgmt.ops.dmaic_phases | DMAIC — методология шести сигм | METHOD | DMAIC (Определить, Измерить, Анализировать, Улучшить, Контролировать): Определить: проблему, CTQ, голос клиента (VOC). Измерение: текущая производительность (базовый уровень), анализ системы измерений. Анализ: анализ первопричин, «Рыбная кость», 5 «Почему». Улучшение: создание решений, пилотное тестирование. Контроль: План контроля, СПК, технологическая документация. | DFSS (Design for Six Sigma): DMADV для новых продуктов/процессов. |
| qualitymgmt.ops.spc_control_charts | SPC — Выбор контрольной карты | METHOD | Статистическое управление процессом (SPC): Xbar-R chart: для малых подгрупп (n<10), непрерывные данные. Xbar-S chart: для больших подгрупп. I-MR chart: для индивидуальных наблюдений. P chart: доля дефектов (p). Np chart: количество дефектов. C chart: дефекты на единицу (постоянный объём). U chart: дефекты на единицу (переменный). | 8 Nelson rules: специальные причины в контрольных картах. |
| qualitymgmt.ops.process_capability | Возможности процесса — Cp Cpk | METHOD | Возможности процесса: Cp = (USL - LSL) / (6σ). Cpk = min[(USL - μ) / (3σ), (μ - LSL) / (3σ)]. Cp ≥ 1.33 (target). Cp = Cpk: центрированный процесс. Pp, Ppk: долгосрочный (total sigma). Sigma Level: 6σ = 3.4 DPMO (с 1.5σ shift). Process Capability Study: ≥50 точек стабильного процесса. | Cp vs Cpk: Cp = ширина допуска. Cpk = с учётом центрирования. |
| qualitymgmt.ops.fmea_design | FMEA — номер приоритета риска | METHOD | FMEA (Failure Mode and Effects Analysis): для каждого потенциального вида отказа. S = Severity (влияние, 1-10). O = Occurrence (вероятность, 1-10). D = Detection (способность обнаружения, 1-10). RPN = S × O × D. Высокий RPN → приоритизировать действие. Design FMEA (DFMEA) vs Process FMEA (PFMEA). AIAG-VDA FMEA 2019: новый стандарт. | AIAG-VDA 2019: AP (приоритет действия) вместо порога RPN. |
| qualitymgmt.ops.gage_repeatability | Гейдж R&R — MSA | METHOD | Анализ измерительных систем (MSA): Gage R&R: повторяемость (оборудование) + воспроизводимость (оператор). GRR % = √(Var_GRR) / Вариация исследования × 100%. <10% = отлично. 10-30% = предельно (возможно приемлемо). >30% = неприемлемо. Количество исследований: мин 10 частей × 3 оператора × 2 повторения. | Если GRR > 30%: измерение ненадёжно → сложно управлять процессом. |
| qualitymgmt.ops.ppap_levels | PPAP — уровни подачи | METHOD | Процесс утверждения производственных деталей (PPAP, AIAG): уровни 1–5. Уровень 1: Только ордер. Уровень 2: Ордер + ограниченное количество образцов. Уровень 3 (стандартный): Ордер + подтверждающие данные. Уровень 4: ориентированный на клиента. Уровень 5: полный пакет у поставщика. 18 элементов PPAP: проектные записи, инженерные изменения, PFMEA, план управления, MSA, первоначальные исследования процесса, квалифицированная лабораторная документация и т. д. | PPAP не утверждён → нельзя отгружать серийную продукцию. |
| qualitymgmt.ops.control_plan | План контроля — документация | METHOD | Контрольный план: определяет контроль входных параметров + параметров процесса + выходных. Columns: Process Step, Characteristic, Spec, Measurement Method, Frequency, Sample Size, Control Method, Reaction Plan. Pre-launch vs Production. Связан с PFMEA (same characteristics). Реакционный план: что делать при выходе за пределы. | Control Plan = обязательный PPAP элемент. |
| qualitymgmt.ops.8d_problem_solving | 8D — Решение проблем | METHOD | Метод 8D (Форд): Формирование команды D1. D2 Описание проблемы. D3 Временные меры по сдерживанию (ICA). D4 Анализ первопричин. D5 Постоянное корректирующее действие (PCA). D6 Реализация и проверка. D7 Предотвратить рецидив. D8 Команда признания. Заказчик требует 8D отчёт при несоответствии. | «Permanent Corrective Action» vs «Interim»: ICA = остановить кровотечение, PCA = устранить причину. |
| qualitymgmt.ops.lean_five_s | Бережливое производство — методология 5S | METHOD | Метод 5S: Sort (Сортировка — удалить ненужное). Set in Order (Систематизация — «место для всего»). Shine (Содержание в чистоте). Standardize (Стандартизация — документировать). Sustain (Совершенствование — аудит, maintenance). Shadow boards (хранение инструментов). 5S + Safety = 6S. | 5S: basis для Lean Manufacturing (без порядка — нет контроля). |
| qualitymgmt.ops.statistical_sampling | Выборка — AQL | METHOD | Приёмочный уровень качества (AQL): ISO 2859-1 (MIL-STD-1916): уровень AQL = максимально допустимый % дефектных. Размер выборки: по уровню контроля + размер партии. Нормальная, усиленная, уменьшенная выборка. Кривая эксплуатационных характеристик (OC): вероятность принятия против % дефектов. Критический/Основной/Незначительный: разные AQL. | AQL 1.0 для критических: 1 дефект из 100 максимально приемлем. |
| qualitymgmt.ops.voc_quality_function | VOC — развертывание функции качества | METHOD | Голос клиента (VOC): VOC → QFD (Дом качества). Что против Как. Требования заказчика → Технические требования. Матрица корреляции: отношения между хорошими. Конкурентный бенчмаркинг. Взвешенная важность. Модель Кано: Обязательно, Одномерная, Привлекательная (восторг). | Кано: «Должно быть» неудовлетворенность → огромное недовольство. «Восторг» → неожиданное удовлетворение. |
| qualitymgmt.ops.poka_yoke | Poka-Yoke — защита от ошибок | METHOD | Защита от ошибок (Пока-Йоке, Синго): не опирается на человека. Типы: Контакт (согласование формы), Предупреждение (оповещение), Управление (остановка процесса). Уровни: Устранение ошибок → Предупреждение → Обнаружение → Смягчение. Примеры: USB только в одном направлении, направляемые разъемы, счетчики при сборке. 100% проверка против профилактики. | Poka-yoke > statistical sampling: предотвращение лучше обнаружения. |
| qualitymgmt.ops.isoiatf16949 | IATF 16949 — Качество автомобилей | METHOD | IATF 16949:2016 (предшественник ISO/TS 16949): Автомобильная промышленность соответствует ISO 9001:2015. Требования заказчика (CSR): OEM предъявляет свои требования. Встроенные требования (из старых Core Tools): APQP, PPAP, FMEA, SPC, MSA. Гарантийный/гарантийный анализ. Требования к лаборатории.
