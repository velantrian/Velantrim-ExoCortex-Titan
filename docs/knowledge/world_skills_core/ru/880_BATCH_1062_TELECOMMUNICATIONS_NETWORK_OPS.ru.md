| telecom.ops.bgp_routing | BGP — протокол пограничного шлюза | METHOD | BGP (протокол пограничного шлюза): межавтономная маршрутизация (EGP). Атрибуты пути: AS-PATH, LOCAL-PREF, MED, NEXT-HOP, ORIGIN. iBGP против eBGP: iBGP (внутри AS, предотвращение петель = не повторно рекламировать), eBGP (между AS). | telecom.ops.mpls_label_switching | MPLS — пересылка на основе меток | METHOD | MPLS (многопротокольная коммутация по меткам): метки (метки) вместо IP-маршрутизации. Входной LER: добавьте метку MPLS. Core LSR: пересылка по метке (без поиска IP). Выходной LER: убрать метку. Стек этикеток: несколько меток. Управление трафиком (MPLS-TE): явная маршрутизация. VPN (L3VPN, L2VPN): услуги на базе MPLS. | MPLS быстрее: неглубокий IP-поиск в ядре (метка = фиксированная длина). |
| telecom.ops.qos_dscp_marking | QoS — маркировка DSCP | METHOD | Качество обслуживания (QoS): DSCP (кодовая точка дифференцированных услуг): 6 бит в IP-заголовке. Организация очереди: приоритетная очередь (PQ), CBWFQ, WFQ. Контроль против формирования: контроль = удаление, формирование = задержка. | VoIP: нужен EF + буфер джиттера <150 мс для речи. |

Разнос поднесущих: 15 кГц (FR1), 30 кГц, 60 кГц (FR1), 120 кГц (FR2). Полоса пропускания: 5–100 МГц (FR1), 50–400 МГц (FR2). Архитектура НР: gNB (базовая станция), разделение CU/DU. | telecom.ops.voip_codec_sip | VoIP — SIP-сигнализация | METHOD | VoIP: SIP (Протокол инициирования сеанса): установление/завершение сессий. RTP (транспортный протокол реального времени): медиапоток. MOS (средний балл мнения): 1–5 (>4 = хорошо). | Буфер джиттера: обеспечивает задержку пакетов. Слишком большое → задержка. Слишком маленький → зазор. |
| telecom.ops.sdwan_overlay | SD-WAN — оверлейная архитектура | METHOD | SD-WAN (Software-Defined WAN): управление несколькими WAN (MPLS + Internet + 4G). Controller: централизованная политика. Vendors: Cisco Viptela, VMware VeloCloud, Aruba. | SD-WAN против MPLS: Интернет + IPSEC = 80 % стоимости, аналогичная производительность для большинства приложений. |

| telecom.ops.tcp_congestion_control | TCP — контроль перегрузки | METHOD | TCP управление перегрузкой: Медленный старт: cwnd = 1 MSS → экспоненциальный рост до ssthresh.
