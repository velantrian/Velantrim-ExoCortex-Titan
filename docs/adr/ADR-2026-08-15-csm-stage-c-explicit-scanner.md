# ADR — CSM Stage C explicit manifest-driven scanner

Date: 2026-08-15  
Status: **PROPOSED IN DRAFT PR #335**  
Issue: #333  
Admission base: `main@43e20f2a777079bf382c4c6512061edb83c6c0d5`

## Context

PC-01 / Code Structural Memory Stage B established immutable structural contracts, content-addressed repository snapshots and a dedicated repository/snapshot-scoped SQLite schema. It intentionally contained no scanner, parser execution, lifecycle owner, query API, background work or runtime authority.

The next bounded gap is to materialize those contracts from repository files while preserving four accepted properties:

1. repository content is untrusted data;
2. `generation` is stale-writer fencing/custody metadata, not semantic snapshot identity;
3. incomplete structural coverage must not be silently promoted as current;
4. CSM remains derived/rebuildable and never becomes Titan Canon/truth/action authority.

A scanner that begins by automatically enumerating Git, starting watchers, adopting Tree-sitter/LSP infrastructure, or exposing MCP would combine multiple independent design decisions and create a larger authority/security surface than needed to prove the core lifecycle.

## Decision

Admit one explicit, local, Python-only Stage-C scanner baseline.

### Invocation

Scanning requires two explicit caller operations:

1. register one repository ID against a resolved local-root fingerprint;
2. invoke `scan_python_repository()` with a bounded caller-provided list of repository-relative paths.

There is no automatic startup scan, watcher, daemon, scheduler, background worker, server endpoint or MCP adapter.

### Parser

Use Python stdlib `ast` as the first deterministic parser baseline.

Persist only:

- `MODULE`, `CLASS`, `FUNCTION`, `METHOD` nodes;
- directed `CONTAINS` edges;
- typed unresolved `IMPORTS` edges;
- source byte spans and parser provenance.

Do not persist source bodies, comments, docstrings, literal/default values or runtime values.

Tree-sitter, LSP/SCIP and semantic resolution remain later benchmark/evidence decisions rather than Stage-C hard dependencies.

### CSM-local lifecycle storage

Evolve only the dedicated CSM database from schema v1 to v2.

Add a repository-scoped lifecycle owner for:

- monotonic scan generation allocation;
- current semantic snapshot / latest scan generation / latest receipt pointer;
- one expiring repository scan lease;
- immutable operational lease events;
- exact receipt/current-generation/current-snapshot binding.

These operational rows are not Titan AuditChain and do not receive Canon or policy authority.

### Source attestation

The filesystem-only scanner is not allowed to claim a clean Git commit.

Every candidate generated by this baseline records:

```text
dirty = true
commit_sha = None
```

A separate Git-aware source-attestation adapter is required before clean-commit claims can be admitted.

### Completeness

The first Stage-C promotion policy is strict:

- any omission or read/parser failure produces `INCOMPLETE_REJECTED`;
- deterministic reason counts are retained in the scan receipt;
- the prior current snapshot remains unchanged.

This avoids inventing a complex completeness threshold before evidence exists.

### Generation and content identity

Keep `generation` outside `snapshot_id`.

Repeated identical scans may allocate newer scan generations and receipts while reusing the same content-addressed semantic snapshot. Before reuse, the materialized semantic header, nodes and edges must match the deterministic candidate.

### Atomic finalization

A complete candidate can become current only in one SQLite finalization transaction after exact lease-token/generation/non-expiry verification.

The transaction binds:

- immutable scan receipt;
- new semantic snapshot materialization, or validated reuse of an existing one;
- current-scan snapshot/generation/receipt pointer;
- final lifecycle event.

A failed transaction cannot replace the prior current snapshot.

## Alternatives considered

### Start with Tree-sitter

Rejected for Stage C baseline. Tree-sitter remains promising, but parser dependency/version/language-pack lifecycle should follow a deterministic stdlib baseline and Titan-specific evidence rather than become an architectural prerequisite.

### Use `core/backends/sqlite_graph.py`

Rejected. Its generic associative graph semantics and reverse-edge behavior do not satisfy directed repository structural identity, repository/snapshot isolation or Stage-C lifecycle custody.

### Use Git commands inside the scanner

Rejected for this slice. Git source attestation is a distinct authority/evidence boundary. The scanner stays honest by recording dirty/no-commit rather than inferring cleanliness.

### Automatically enumerate the repository

Deferred. Explicit caller manifests make the first scanner testable without introducing ignore rules, tracked-file semantics, generated/vendor policy or filesystem discovery authority in the same PR.

### Promote partial scans

Rejected for v1. A partial index may be useful later, but it needs explicit profile-aware coverage semantics. The first executable scanner fails closed instead.

### One physical snapshot per generation

Rejected. It would put custody time/order into semantic identity indirectly and duplicate identical structural materialization. Content identity and scan observation generation remain separate.

## Consequences

### Positive

- Stage C is executable without adding a model, network or external parser dependency.
- Source-code execution is not required.
- Snapshot promotion has an explicit stale-writer boundary.
- Failed/incomplete scans cannot silently become current.
- Repeated equivalent scans remain semantically deterministic.
- The implementation preserves the Stage-B content-addressed identity model.

### Limitations / follow-up

- Python only.
- Explicit manifests only.
- All scans are dirty/no-commit until Git-aware attestation exists.
- Symlink/root containment is bounded by path resolution and pre/post checks; no hostile-filesystem descriptor-level sandbox guarantee is claimed.
- No incremental/watch mode.
- No read/query API.
- No cross-repository relations.
- No Project Cognition/ContextPack admission.
- Operational scan events are not a second audit authority.

## Authority impact

**NONE beyond bounded CSM derived-storage lifecycle.**

Unchanged:

- PolicyKernel remains sole permission owner;
- Canon remains authoritative memory state;
- TruthGate/WriteGate/ESM ownership unchanged;
- Titan project-state schema remains v7;
- Continuity remains 12/12;
- runtime enabled remains false;
- Operator GO remains false;
- runtime/production authority remain false.

This ADR does not admit Stage D or later Project Cognition/runtime integration.
