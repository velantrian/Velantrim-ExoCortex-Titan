# PR-RDR-01 — Deterministic Document Structure Map

**Status:** `IMPLEMENTED_IN_BRANCH / SHADOW_FOUNDATION / NO_RUNTIME_WIRING`  
**Depends on:** PR-RDR-00 contracts  
**Authority:** `DERIVED / REBUILDABLE / NO_CANON_OR_MEMORY_AUTHORITY`

## Purpose

PR-RDR-01 implements the first deterministic producer of `DocumentStructureMap` values. It reads immutable `RawSource` text directly and preserves Python Unicode code-point offsets into that exact source revision.

It does not consume the transformed output of the legacy file parsers because frontmatter removal, JSON formatting, encoding replacement, or other transformations could make offsets diverge from the original evidence.

## Supported formats

### Plain text

Plain text is represented conservatively as one full-source section:

```text
Document
└── offsets 0..EOF
```

No semantic heading inference is attempted. The map and section carry `plain_text_single_section` warnings so downstream components know that no explicit hierarchy was observed.

### Markdown

The first Markdown slice supports:

- ATX headings from level 1 through 6;
- up to three leading spaces before a heading;
- optional closing heading hashes;
- exact source offsets;
- a source-covering preamble before the first heading;
- nearest-lower-level parent assignment;
- deterministic previous and next links;
- fenced code exclusion for backtick and tilde fences;
- deterministic placeholders for empty headings.

Setext headings, HTML block parsing, tables, footnotes, frontmatter typing, and embedded asset extraction are intentionally not inferred in this slice. A Markdown document without ATX headings degrades to one full-source section with an explicit warning.

## Full-partition invariant

Every successful structure map covers the complete source exactly once:

```text
first.start_offset == 0
last.end_offset == len(source.text)
previous.end_offset == current.start_offset
```

Sections cannot overlap and cannot leave hidden gaps. Leading whitespace before the first Markdown heading is retained as a `Preamble` section rather than discarded.

## Revision and identity

When `RawSource.source_revision` is present, it is preserved unchanged. Otherwise PR-RDR-01 derives a deterministic revision:

```text
sha256:<SHA-256 of exact UTF-8 source text>
```

`section_id` remains generated by the PR-RDR-00 contract. `map_id` includes:

- schema version;
- document identity and source revision;
- parser identity and version;
- exact content hash;
- ordered section identities.

Unchanged input therefore produces unchanged structure and map identities.

## Hierarchy rule

For each Markdown heading, the parent is the nearest preceding heading with a lower numeric level.

```text
# Root
## Child        → parent: Root
### Grandchild → parent: Child
# Next Root     → parent: none
```

A preamble is navigational source coverage and is not made the parent of the first root heading.

## Safety boundary

The parser:

- uses only standard-library deterministic operations;
- makes no model or network call;
- performs no tool execution;
- has no persistence side effects;
- is not wired into `/query`;
- cannot write Canon;
- cannot admit memory;
- cannot bypass TruthGate or Write Gate;
- treats all source text as untrusted data.

## Fixtures and executable checks

Fixtures:

- `tests/fixtures/reader_core/rdr_01_plain_text.txt`
- `tests/fixtures/reader_core/rdr_01_markdown.md`

Tests verify:

- exact source hashing and derived revisions;
- complete source partitioning;
- stable map and section identities;
- Markdown hierarchy;
- previous and next navigation links;
- ignoring heading-like text inside fenced code;
- conservative fallback when ATX headings are absent;
- rejection of empty or whitespace-only documents.

## Deferred to later slices

PR-RDR-01 intentionally does not implement:

- hierarchy-aware bounded reading units — PR-RDR-02;
- SectionCards — PR-RDR-03;
- exception and coverage computation — PR-RDR-04;
- selective rereading — PR-RDR-05;
- cross-section semantic relations — PR-RDR-06;
- durable sessions, leases, or crash recovery — PR-RDR-07;
- global synthesis — PR-RDR-08;
- promotion thresholds and real-corpus evaluation — PR-RDR-09.

It also does not replace the existing file-ingestion parsers. A later adapter may pass exact extracted text into Reader Core only when provenance guarantees that offsets still refer to immutable source evidence.
